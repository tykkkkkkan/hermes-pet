## 二、能照搬 vs 不能照搬

### 能照搬的机制

| 机制 | 为什么能搬 |
|---|---|
| 记忆按会话/中期/长期分层，并设置上下文预算 | 是存储与上下文组织方式，不依赖大肥鱼的人设；当前应以 Hermes 的 `USER.md`、`MEMORY.md` 为长期事实来源，避免平行记忆冲突 |
| 人设配置与字段锁分离 | 配置保护机制与具体角色无关；可保留 Hermes 专属内容，同时避免模型覆盖用户锁定字段 |
| 热区 × 人格 → 动作的映射表 | 数据驱动的交互组织方式与角色立绘无关；热区坐标、台词和动作素材必须使用本项目自己的资源 |
| 状态事件驱动表情/播报 | 事件归一、状态转换和播报去重属于通用机制；事件源可直接使用现有 Hermes 快照 |
| 只追加事件日志、按需生成投影 | 便于追溯状态变化，且避免单个可变快照成为唯一事实来源；落盘结构可以适配现有 JSON |
| 16k 音频采样、能量 VAD、静音裁剪 | 是通用音频前处理；具体识别引擎、模型文件和依赖需独立评估，不复制其 vendor |
| TTS 文本分句、缓存键、失败重试与明确报错 | 属于通用合成管线；音色、服务和失败回退应选择本项目可用方案 |
| 工具权限分级与执行前确认 | 属于电脑操作安全边界；可沿用原则，权限项目必须按本机风险重新定义 |
| 事件总线与模块职责拆分 | 降低功能之间直接互相调用的耦合，可增量加模块而不重写现有主进程 |
| 命名空间存储和原子写入 | 属于通用本地数据可靠性机制；需兼容目前文件，不能直接替换/迁移数据而不确认 |

### 不能照搬

- 人设立绘、台词、人格设定：参考对象是「吃白饭的大肥鱼」二创，有独立版权。
- `vendor/whisper`、`vendor/ws` 等几十 MB 的二进制/依赖目录：不复制到本项目。
- 参考项目的 UI 配色和布局：不照搬视觉设计。
- 参考项目的音色选择、在线服务参数和模型配置：只参考机制，不复制可能不适用于本项目的服务配置或凭据。
