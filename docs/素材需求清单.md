# 赫尔墨兹 · 立绘素材需求清单

> 目的：说清「最终要准备哪些图、每张什么规格、对应什么状态」，照着出图即可接入。
> 结论前置：**一共 8 张全身立绘，你已有 1 张，还差 7 张。**

---

## 一、为什么是 8 张，而不是 106 张

参照对象 `MerZlin/dsh-pet-indesktop` 的深海色角色包，一共 **106 个 webm 动画**，但按目录拆开看，它们是分层的：

| 目录 | 数量 | 性质 | 能否用静态图替代 |
|---|---|---|---|
| `idle/` | 1 | 待机 | ✅ 能（呼吸靠 CSS） |
| `click/` | 4 | 点击回应 | ✅ 能（换图 + 抖动） |
| `drag/` | 1 | 拖拽悬空 | ✅ 能 |
| `move/` | 3 | 移动 | ⚠️ 半能（原地姿态 + CSS 位移） |
| `turn/` | 1 | 转向 | ⚠️ 半能（水平翻转） |
| `events/balance/` | 6 | 业务事件（余额） | ✅ 能 |
| **`random/`** | **89** | **随机小剧场** | ❌ 不能 |

**功能性的只有 16 个，剩下 89 个是小剧场**（吃饺子、放烟花、写福字、舞狮头……）。

小剧场是"内容"，不是"状态"。它决定这只桌宠有多少彩蛋，不决定它能不能用。所以第一版**不做小剧场**，先把 16 个功能位压缩成 8 张静态图。

---

## 二、8 个状态，对应 8 张图

这 8 个不是随便定的，是照 `dsh_state.py` 里的八状态收敛模型来的（`offline / idle / thinking / working / waiting_approval / success / error` + 两个交互态）。

| # | 状态 | 图上画什么 | 何时切到这张 | 大肥鱼对应动画（可去仓库对照） |
|---|---|---|---|---|
| 1 | **idle** | 正面站姿，自然垂手 | 默认常驻 | `idle/待机呼吸休闲` ✅**已有** |
| 2 | **thinking** | 一手托腮/摸下巴，视线微偏 | Codex 在推理、Agent 思考中 | `random/深度思考碎碎念`、`工作状态-思考冒泡` |
| 3 | **working** | 前倾敲键盘 / 双手忙碌 | 正在执行工具、跑编译 | `random/写代码`、`工作状态-忙碌点按` |
| 4 | **waiting** | 举手示意 / 递东西的姿势 | 需要你确认、等你回话 | `工作状态-原地踱步张望` |
| 5 | **success** | 开心跃起 / 双手上举 | 任务完成、测试通过 | `click/点击回应-开心跃动`、`工作状态-雀跃庆祝` |
| 6 | **error** | 垂头、冒汗、肩膀塌下 | 报错、失败、卡住超时 | `工作状态-垂头叹气冒汗` |
| 7 | **sleepy** | 打哈欠 / 揉眼睛 / 快睡着 | 长时间无操作、深夜 | `random/哈欠连天`、`原地小憩沉眠` |
| 8 | **annoyed** | 叉腰、鼓腮、瞪人 | 被反复拖拽、被戳太多次 | `click/点击回应-傲娇生气` |

**已有：01 站姿 → 直接当 #1。还需 7 张。**

这 7 张不是"七种表情"，是**七个姿势**。表情要跟着姿势一起变，但主体是身体姿态——因为桌宠在桌面上是小尺寸（350–450px），只有姿势变化能被看见，纯换脸看不出来。

## 三、硬规格（这 6 条不满足，切图就会跳）

任何一条不达标，切状态时人物会突然变大、变小、上下窜，观感立刻崩。

| 项 | 要求 | 原因 |
|---|---|---|
| **画布** | 1024 × 1024，透明底 PNG | 与现有 `body/idle.png` 完全一致，可原地替换 |
| **角色高度** | 统一占画布 **80%**（约 819px） | 身高不一致 = 切换时缩放跳变 |
| **脚底位置** | 统一在 **y = 0.95**（距底 5%，约 973px） | 脚底不固定 = 人物上下窜 |
| **水平位置** | 身体中轴统一在 **x = 0.5**（512px） | 不居中 = 左右跳 |
| **视角** | 一律正面，不侧身、不俯仰 | 视角变了就是另一个人 |
| **光照** | 主光统一来自**左上**，阴影落右下 | 光照不一致 = 像拼贴 |

补充两条内容约束：

- **同一套服装、同一发型、同一配饰**，包括裙子褶皱走向、翅膀张角
- **不要画地面、不要画影子、不要画背景**，影子由程序加（`fx/shadow.png`）

## 四、出图方法：不是"重新生成"，是"同角色改姿势"

这一点最关键。直接写新提示词从零生成，出来的一定是另一个角色。

**正确做法是用参考图驱动**：

1. 拿 `01-站姿-常驻形象.png` 当参考图（image reference / 垫图）
2. 提示词只描述**变化的部分**（姿势、表情），角色描述保持不动
3. 参考强度调到中高（能锁住角色，又允许姿势变）
4. 一次只改一个变量：先只改姿势 → 再只改表情

**提示词骨架**（把方括号里的替换掉）：

```
与原图完全相同的角色：银白长发、白裙、羽翼、[配饰细节]，
保持同一画风、同一光照（左上方主光）、同一服装细节。
只改变姿势：[一手托腮，视线微微下垂，身体略前倾]。
全身正面站姿，人物高度占画面 80%，脚底位于画面底部上方 5%，
居中，纯透明背景，不要地面、不要投影、不要任何背景元素。
```

七张分别替换方括号里的姿势描述：

| 图 | 姿势描述 |
|---|---|
| thinking | 一手托腮，手肘撑起，视线微微下垂，另一手轻握 |
| working | 身体前倾，双手在身前作敲击状，眉头微皱，专注 |
| waiting | 一手举起示意，身体略侧，表情期待地看着前方 |
| success | 双臂上举，身体腾空，笑得灿烂，头发与裙摆上扬 |
| error | 肩膀塌下，头微垂，额头一滴汗，嘴角下撇 |
| sleepy | 一手揉眼，张嘴打哈欠，身体微微摇晃，眼皮半闭 |
| annoyed | 双手叉腰，鼓腮，眉毛竖起，侧目瞪视 |

## 五、出完图之后我会做什么

拿到 7 张原图后，跑现有脚本即可自动对齐：

```
node tools/build-pet-3d.js
```

它会：按内容包围盒算出每张的实际身高和脚底位置 → 统一缩放到 80% / 脚底 0.95 → 居中 → 做立体化（清晰度 + 凹陷遮蔽 + 暗部边缘光）→ 生成对应落影 → 写入 `manifest.json`。

**所以原图不需要你自己对齐**，画布大一点、位置偏一点都没关系，脚本会重算。你只需要保证**角色本身画得一致**。

## 六、静态图的极限在哪（实话）

| 效果 | 静态图 + CSS | 真动画（webm） |
|---|---|---|
| 呼吸起伏 | ✅ 几乎无差别 | ✅ |
| 状态切换（思考→干活→完成） | ✅ 够用 | ✅ |
| 点击抖动回应 | ✅ 够用 | ✅ |
| 拖拽跟随 | ✅ 够用 | ✅ |
| 走路 / 转身 | ⚠️ 只能"原地踏步 + 位移"，脚不迈 | ✅ |
| 小剧场（吃饺子、放烟花…） | ❌ 完全做不到 | ✅ |

换句话说：**8 张图能做到"它会看着我、会累、会生气、会庆祝"，但做不到"它自己在玩"**。

想要后者，路子是把这 8 张当角色参考，用 AI 生成 10 秒绿幕视频再抠像转 webm（大肥鱼就是这么做的）。那是另一个量级的工作，等静态版跑通再谈。
