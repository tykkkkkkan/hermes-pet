## 三、真 bug（会实际出问题的）

### B1 · Hermes 离线时点「新建任务」会卡住【实查，代码可见】

`renderer/chat.js:341-343`：

```js
async function openTaskModal(files = []) {
  droppedFiles = files.filter(Boolean);
  const snapshot = await window.pet.getHermesSnapshot();   // ← 没有 try/catch
  const assignees = (snapshot.agents || []).map((agent) => agent.name);
```

`getHermesSnapshot` 走主进程 → `hermes-bridge` → HTTP 请求 Hermes。Hermes 没起来时这里会抛，`openTaskModal` 直接中断，**弹窗不出现、也没任何提示**，用户点「新建任务」看起来就是没反应。

对比一下：`init()` 那个入口是有 `.catch()` 兜底的（`chat.js:684`），说明作者知道要兜，但这一处漏了。

修法：包 try/catch，失败时用 `['default']` 兜底并提示「Hermes 离线，先派给默认执行端」。

### B2 · 路径校验可以被同名前缀目录绕过【实查，可构造】

`main.js:711-715`：

```js
const rel = decodeURIComponent(pathname).replace(/^\/+/, '');
const target = path.normalize(path.join(__dirname, rel));
if (!target.startsWith(__dirname)) {
  return new Response('forbidden', { status: 403 });
}
```

`startsWith` 少了分隔符。假设 `__dirname = D:\01-项目\hermes-pet`，而磁盘上存在 `D:\01-项目\hermes-pet-备份`，那么 `petasset://app/../hermes-pet-备份/x.png` 归一化后得到 `D:\01-项目\hermes-pet-备份\x.png`，`startsWith(__dirname)` 为真，**检查通过**。

这是本地协议，攻击面是「渲染进程里如果有 XSS，能读到自己目录旁边的文件」。结合 B2 的风险等级，属于低-中。

修法：

```js
const base = path.resolve(__dirname);
const target = path.resolve(base, rel);
const relCheck = path.relative(base, target);
if (relCheck.startsWith('..') || path.isAbsolute(relCheck)) {
  return new Response('forbidden', { status: 403 });
}
```

### B3 · Markdown 里的链接会被转义坏掉【实查，代码可见】

`renderer/chat.js:32-35`：

```js
src = esc(src)
  .replace(/`([^`\n]+)`/g, '<code>$1</code>')
  .replace(/(https?:\/\/[^\s<)）]+)/g, '<a href="$1" target="_blank" rel="noreferrer">$1</a>');
```

先 `esc()` 再拼 `<a href>`，顺序是对的（防 XSS）。但 `esc()` 会把 `&` 变成 `&amp;`，所以带查询参数的链接（`https://example.com/a?x=1&y=2`）在 `href` 里变成 `&amp;`，**点开是坏的**。

修法：在生成 `<a>` 时把 `$1` 里的 `&amp;` 还原成 `&`：

```js
.replace(/(https?:\/\/[^\s<)）]+)/g, (m) => {
  const href = m.replace(/&amp;/g, '&');
  return `<a href="${href}" target="_blank" rel="noreferrer">${m}</a>`;
})
```

### B4 · `formatUtterance` 直接改状态对象内部字段【实查，设计债】

`main.js:96-112`：

```js
petState.address = address;
petState.addressHistory = [...history, address].slice(-2);
```

`petState` 是 `petStateStore.get()` 返回的**内部对象引用**。这里绕过了 `petStateStore.set()` 直接写字段，等于状态模块管不着自己的状态。目前能跑（因为引用是同一个），但下次谁在 `pet-state.js` 里加个校验或变更通知，这里就会被漏掉。

不算 bug，算债。修法：改成 `petStateStore.set({ address, addressHistory })`。

## 四、安全面

| 项 | 结论 |
|---|---|
| API 密钥存储 | `safeStorage` 加密后落盘，解密失败返回空字符串。✓ 合格 |
| 密钥是否进日志 | 曾经会（记录长度和 base）。已在 `fdd2ef1` 修成只报「已导入」✓ |
| 桥接 token | 32 字节 `crypto.randomBytes`，`Authorization: Bearer` 校验 ✓ |
| token 文件权限 | 明文写在 `%LOCALAPPDATA%\hermes\hermes-pet-bridge.json`，**本机任何进程都能读**。这是「本机可信」的信任模型，自用工具可接受，但要知道这层不存在防护 |
| token 比较方式 | `String(...) === \`Bearer ${token}\`` 不是常量时间比较，理论上有计时侧信道。本地 127.0.0.1 + 32 字节随机，**实际风险可以忽略**，不修 |
| 渲染层 XSS | `renderMarkdown` 先转义再生成标签，`showInspector` 的 skill 名和内容也 `esc()` 过 ✓ 合格 |
| 路径穿越 | 见 B2 |
| 请求体大小限制 | `readBridgeBody` 超过 100KB 拒绝 ✓ |
| 消息长度限制 | `chat-send` 截断到 4000 字符 ✓ |

## 五、视觉问题（看实机截图得出）

拿 `docs/pet-action-idle.png` 逐项看的：

**好的部分**：立绘清晰、没有白边锯齿；头部和身体接缝看不出来（拆层做得干净）；脚底投影位置正确；文字可读性没问题。

**要改的部分**：

1. **气泡和状态药丸的外圈光晕发糊**。气泡四周那一圈紫色渐变边缘是虚的，尤其左下角和右侧，像素材的阴影层被 9-slice 拉伸放大了。现在气泡是「三态着色 + 9-slice」，着色时给整张图加了外发光，拉伸后发光层跟着变形。
   → 建议：外发光不要做在 9-slice 素材里（会被拉伸），改成 CSS `box-shadow` 或者 `filter: drop-shadow()`，这样发光不随尺寸变形。

2. **气泡右下角有一片紫色晕染**，位置不对称。同一原因。

3. **状态药丸「Hermes 离线」的边框和气泡不统一**：药丸是细描边 + 外发光，气泡是粗描边 + 更强的外发光，两个元素挨在一起，观感不整齐。
   → 建议：统一描边粗细和发光强度，或者干脆药丸不做发光。

4. 角色脚底右下角有一个**小蓝点**（截图里能看到），像是 fx 粒子没清干净或者投影的边缘像素。不影响使用，但属于「成品不该有」。

## 八、优化建议（按性价比排序）

### 第一优先：修 B1、B2、B3

都是几十行的改动，B1 是体验问题（点了没反应最伤），B2 是安全，B3 是功能。一轮能做完。

### 第二优先：给 `normalizeBoard` 补单测

它是三处 UI 的数据源头，纯函数，好测。补完之后 `hermes-bridge.js` 的核心逻辑就有了回归网。

### 第三优先：视觉修那三处（发光、晕染、药丸统一）

这是「像不像成品」的分界线。现在的立绘和分层已经很好了，被气泡外圈那圈糊掉的发光拖了后腿。

### 第四优先：语音输入（要你拍板）

实测确认必须装本地引擎。最省的组合是 sherpa-onnx 流式中文模型 70.6MB + VAD 0.6MB，合计约 71MB。装了就有点「这个桌宠能听我说话」的质变，不装就一直是个死按钮。

### 第五优先：自动更新 + Hermes 启动自动拉起

这两个是「日常用起来顺不顺」的问题，不影响功能，但每次手动操作会累积烦躁。
