# 第一部分：修视觉验收截图（P0，先做这个）

## 1.1 为什么截出来是空白

`neck-cut-zoom-4x.png` 只有 1909 字节，打开是整张空白。原因在 `test/e2e/pet-smoke.mjs:291-298`：

```js
const vp = window.petLive2d?.getViewport?.();
const y0 = vp.rootY + 240 * vp.scale;
const y1 = vp.rootY + 310 * vp.scale;
return { x: Math.max(0, vp.rootX - 20), y: Math.max(0, y0), ... };
```

`getViewport()` 返回的 `rootX` / `rootY` 是 **canvas 内部坐标**（相对 canvas 左上角），而 `Page.captureScreenshot` 的 `clip` 参数用的是 **视口坐标**（相对窗口左上角）。

中间差了 `#pet-live2d-host` 自己的位置。这台机器上 `#pet-live2d-host` 的 `getBoundingClientRect().top` 约 121，所以：

```text
算出来的 y0 = (-1.6) + 240 × 0.44 ≈ 103
实际角色在窗口的 y ≈ 121 往下
```

**裁到了角色头顶以上 18px 的空白区**，所以整张透明。

## 1.2 修法

```js
const seamClip = await evaluate(cdp, `(() => {
  const vp = window.petLive2d?.getViewport?.();
  if (!vp) return null;
  // getViewport() 给的是 canvas 内部坐标，Page.captureScreenshot 要的是视口坐标，
  // 中间必须加上宿主元素自己的位置，否则会裁到角色外面的空白区。
  const host = document.getElementById('pet-live2d-host').getBoundingClientRect();
  const toViewportY = (canvasY) => host.top + canvasY;
  const toViewportX = (canvasX) => host.left + canvasX;
  const y0 = toViewportY(vp.rootY + 240 * vp.scale);
  const y1 = toViewportY(vp.rootY + 310 * vp.scale);
  return {
    x: Math.max(0, toViewportX(vp.rootX) - 20),
    y: Math.max(0, y0),
    width: Math.min(window.innerWidth - Math.max(0, toViewportX(vp.rootX) - 20), 448 * vp.scale + 40),
    height: Math.min(window.innerHeight - Math.max(0, y0), y1 - y0),
    scale: 4
  };
})()`);
```

## 1.3 判定要变严

现在只判 `statSync(file).size > 1000`，1.9KB 的空白图也能过。改成**必须肉眼看得出内容**：

```js
// 空白图的 PNG 压缩后极小；有内容的放大图不可能低于 20KB
const ok = fs.statSync(file).size > 20000;
```

再加一条：算图片的**不透明像素占比**，低于 5% 判失败：

```js
const { PNG } = require('pngjs');
const png = PNG.sync.read(fs.readFileSync(file));
let opaque = 0;
for (let i = 3; i < png.data.length; i += 4) if (png.data[i] > 8) opaque++;
const ratio = opaque / (png.width * png.height);
// 放大 4 倍的脖子区域，角色应该占相当比例
check('切缝放大图有实际内容', ratio > 0.05, `不透明占比 ${(ratio * 100).toFixed(1)}%`);
```

## 1.4 rot 三张也要重拍

`rot-0.png` / `rot-plus8.png` / `rot-minus8.png` 还是 10:56 的旧图，是修过画之前的版本。

用同样的方式重拍，注意也要走 `getPose()` 而不是直接调 `playTrack`——拍之前确认 `getPose().rot` 真的到了 8 度：

```js
const pose = await evaluate(cdp, `window.petLive2d.getPose()`);
check('rot 到达 8 度', Math.abs(pose.rot - 8) < 0.6, `实测 ${pose.rot.toFixed(2)}`);
```

## 1.5 验收

```text
1. neck-cut-zoom-4x.png 的文件大小 > 20KB，不透明占比 > 5%
2. 三张 rot 图的文件大小各 > 100KB（现在 300KB 左右是正常的）
3. 亲自打开看：脖子区域放大后，切缝上下应该连成一片，没有透明缝、没有叠影
4. smoke 仍然 30/30 × 3
```

**第 3 条是这部分的唯一目的。** 数据对了不等于看着对，这次必须人眼过一遍。

# 第二部分：手臂分层（C 档，要先生图）

先说清难度：**这是五项里风险最高的一项。** AI 很难在保持「除手臂外其余像素完全不变」的前提下改手臂姿势，差分出来的手臂层会带噪点。所以分成两步：先生图验证可行性，可行再接入。

## 2.1 先生两张图

沿用 `docs/豆包生图指令-全集.md` 的规矩：参考图只用 `state-idle.png` 那一张，1:1，一次生成 4 张挑最像的，原样保存不抠底。

**指令 A · 右手抬起**

```text
同一个角色，完全相同的站姿、机位、光照、画幅和背景。
只改右手：右臂从身侧抬起，前臂抬起约 45 度，手掌张开朝外，像在打招呼。
左手、身体、头部、表情、头发、裙子、披风、书本、手机的位置和形状完全不变。
保持原有的线稿粗细、上色风格和阴影方向。正方形 1:1。
```

**指令 B · 双手抱胸**

```text
同一个角色，完全相同的站姿、机位、光照、画幅和背景。
只改双手：双臂交叉抱在胸前，手掌各自搭在对侧手臂上。
身体、头部、表情、头发、裙子、披风的位置和形状完全不变。
保持原有的线稿粗细、上色风格和阴影方向。正方形 1:1。
```

文件名：`arm-raise.png`、`arm-cross.png`，放在 `.tmp/ai-raw/`。

## 2.2 先做可行性验证，别急着接入

拿到两张图之后，**先跑一次差分，量一下噪声**：

```bash
node tools/analyze-arm-diff.js   # 需要新写，见下
```

这个脚本要做的事：

```js
// 1. 三张图对齐（state-idle / arm-raise / arm-cross），用和 build-pet-layers 同样的
//    键控 + 包围盒归一化流程
// 2. 算 state-idle 和 arm-raise 的逐像素差，得到「变化区域」
// 3. 统计变化区域的形态：
//    - 变化像素总数
//    - 变化区域的包围盒
//    - 变化区域里，有多少像素是「手臂应有位置」之外的（即 AI 顺手改了别处的噪声）
// 4. 输出差异图 .tmp/arm-diff.png 给人看
```

**判定标准**：

| 结果 | 结论 |
|---|---|
| 变化区域集中在手臂附近，包围盒宽度 < 角色的 60% | ✅ 可用，继续接入 |
| 变化散落在裙子、头发、书本上 | ❌ AI 保持不住，换思路 |
| 身体轮廓整体位移 1~3px | ⚠️ 可接受，对齐后能用 |

**这一步的产出是「能用 / 不能用」的判断，不是手臂层本身。** 不能用就别硬上，把差异图和结论一起报上来，我们换方案（手工圈蒙版、或者干脆不做手臂）。

## 2.3 如果能用：接入

`assets/pet-layers/` 加两张：

```text
arm-raise.png    448×841   raisE 状态下的完整角色（用于差分基准）
arm-cross.png    448×841
```

`meta.json` 加：

```json
"arms": {
  "left":  { "x": 0, "y": 400, "w": 120, "h": 300 },
  "right": { "x": 328, "y": 400, "w": 120, "h": 300 },
  "poses": ["idle", "raise", "cross"]
}
```

`pet-puppet.js` 加两个 sprite（`leftArm` / `rightArm`），定位在 body 层之上、head 层之下。切换时和表情一样用 crossfade。

**`tracks` 里加 `armL` / `armR` 参数**，值域 0（贴身）~1（完全张开），通过切换 `arm-raise` 的可见度实现（不是骨骼，是贴片混合）。

## 2.4 验收

```text
1. 差分噪声的量化结论（能用 / 不能用 + 理由）
2. 差异图 .tmp/arm-diff.png
3. 如果接入：`armL = 0 / 0.5 / 1` 三个状态的截图
4. 挥手动作播放时，手臂真的抬起来而不是整张图晃
```

# 第三部分：走路第二帧（B 档，一张图）

## 3.1 生图

```text
同一个角色，完全相同的机位、光照、画幅和背景。

保持原有的线稿粗细、上色风格和阴影方向。正方形 1:1。
```

文件名：`walk-pass.png`，放 `.tmp/ai-raw/`。

## 3.2 接入

1. 按 `pose-meta.json` 的标定（k=1, ox=-288, oy=-138）归一化成 448×841，输出到 `assets/pet-layers/pose/pose-walk-pass.png`
2. `preload.js` 的 `poseSources` 加 `walkPass`
3. `behavior.js` 加第 10 个状态 `walking`：

```js
walking: { minMs: 600, maxMs: 600, intents: [], attention: 'mouse', locomotion: true }
```

**触发条件**：`idle` 超过 3 分钟、好感度 ≥ 50、鼠标不在窗口内。**别让它一直走**，走 2~4 秒就停。

4. 走路时两帧交替（每帧 500ms），同时窗口位置平移——`main.js` 已经有 `move-to` IPC，用它。

**关键细节**：平移速度要和步频匹配。两帧 500ms 一轮，每轮移动约 12px（角色宽度的 5%），看起来才像在走而不是滑。

```text

2. 走 3 秒的录屏或连续截图，位置的平移速度和步频匹配
3. 走到屏幕边缘会停下，不会走出去
4. 点击窗口立刻停止走路
```

# 第五部分：自动更新（工程收尾）

## 5.1 先说为什么不上 electron-updater

`dist/latest.yml` 其实已经生成了（electron-builder 自动做的），`publish` 没配。上 electron-updater 需要：

- 配置 `publish: [{ provider: 'github', ... }]`
- 每次打包带 `GH_TOKEN` 环境变量
- 有代码签名才能跳过 SmartScreen 警告

对一个自用工具，这套成本高于收益。**建议走轻量方案：检查更新 + 提示下载。**

## 5.2 轻量方案

启动时（延迟 30 秒，别影响启动速度）拉一次远程版本号：

```js
async function checkUpdate() {
  try {
    // raw.githubusercontent 是公开只读的，不需要 token
    const res = await net.fetch('https://raw.githubusercontent.com/tykkkkkkan/hermes-pet/main/package.json', {
      headers: { 'cache-control': 'no-cache' }
    });
    if (!res.ok) return;
    const remote = await res.json();
    const local = app.getVersion();
    if (!remote.version || remote.version === local) return;
    // 只比版本号，不做签名校验——自用工具，用户自己决定装不装
    announce(`{address}，有新版本 ${remote.version}，我现在是 ${local}，要更新的话去仓库下载`, {
      kind: 'system', notify: true, userInitiated: false
    });
    logger.info('[update] 发现新版本', { local, remote: remote.version });
  } catch (error) {
    // 没网、被墙、GitHub 挂了都走这里，静默，不要打扰用户
    logger.warn('[update] 检查更新失败', error.message);
  }
}
```

挂在 `app.whenReady()` 之后：

```js
if (process.env.PET_DISABLE_UPDATE_CHECK !== '1') setTimeout(checkUpdate, 30000);
```

**关键点**：

1. **失败必须静默**。断网、GitHub 404、代理拦截都可能发生，一次弹窗都不能有
2. **用 `net.fetch` 不用 Node `fetch`**——这个坑之前踩过（`ENOTFOUND` 那次），Node 的 undici 不读系统代理
3. **一天只查一次**，记到 settings 里，别每次启动都拉
4. **菜单里加一项「检查更新」**，手动触发时失败要给出提示（和静默自动检查不同）

## 5.3 托盘菜单

```js
{ label: '检查更新', click: () => checkUpdate(true) }   // true = 手动，失败要提示
```

## 5.4 验收

```text
1. 把本地 version 临时改成 0.1.0，启动后 30 秒内出现「有新版本」的播报
2. 断网启动，日志里有 [update] 检查更新失败，但没有任何弹窗
3. 一天内重启三次，只有第一次真的发请求（看日志次数）
4. 托盘菜单「检查更新」点一下，断网时要弹出提示
```

# 不许做的

1. **第一部分不要只改文件大小阈值**。必须同时加「不透明像素占比 > 5%」，否则下次裁到别处又漏过去
2. **第二部分可行性没验之前不要写接入代码**。手臂差分噪声大是常态，先量再说
3. **第三部分不要只接一帧就开走路**。单帧看起来是滑动，比不走还怪
4. **第四部分不要用 `filter: blur` 之类假装眉毛**。要真贴片
5. **第五部分不要引 electron-updater**，也不要加 `publish` 配置
