# 指令 18 · 行为系统：把它做成一个生物

> 目标从「显示状态的桌宠」升级成「一个有内在状态的生物」。Hermes 的智慧不是靠更多台词传达的，而是靠**它的动作能解释为什么**。
> 这份是设计 + 实现，重点在动作行为层。分四步做，每步独立可验。

---

## 一、先纠正一个误解：情绪系统是活的，但动作不认情绪

我一开始以为情绪系统只被调用了一次，查清楚之后发现是错的——7 种事件全在用：

| 事件 | 触发点 | 位置 |
|---|---|---|
| `touched` | 点四个热区 | `main.js:209` |
| `working` | 有任务开始跑 | `hermes-poller.js:67` |
| `success` | 任务完成 / 验收 | `hermes-poller.js:72`、`:83` |
| `failure` | 任务受阻或失败 | `hermes-poller.js:76` |
| `ignored` | 6 小时没理它 | `pet-state.js:103-105` |
| `praised` | 用户说「谢谢/辛苦/做得好」 | `pet-state.js:113` |
| `nagged` | 用户抱怨 | `pet-state.js:121` |

外加 `decay()` 按小时衰减。这套设计是好的。

**真正的缺口是：情绪只影响表情和台词池，完全不影响动作。**

现在的动作选择链（`renderer/pet.js` → `pet-actions.js`）：

```js
function chooseAction(group, previousId) {
  const pool = group === 'all' ? ACTIONS : ACTIONS.filter((a) => a.group === group);
  const candidates = pool.filter((a) => a.id !== previousId);
  return candidates[Math.floor(random() * candidates.length)];
}
```

只按热区分组、只避开上一个。所以：

- 它「闹别扭」的时候，随机抽还是会抽到 `cheer`（欢呼）
- 它「犯困」的时候，照样可能 `quick-hop`（跳起来）
- 好感度 90 和 20，动作一模一样
- 被戳了 20 次和 0 次，除了台词不同，动作没区别

**这就是「不像生物」的根源。** 不是动作不够多，是动作和内在状态脱钩了。

## 二、目标架构

```text
驱动力（每 1 秒算一次）
├─ 精力 energy     ← 一天中的时间 + 昨晚睡了多久
├─ 情绪 emotion    ← 已有，8 种
├─ 关系 affection  ← 已有，0~100
├─ 烦躁 irritability ← 短时间内被戳的次数
└─ 环境 context    ← 任务在跑/卡住、鼠标在不在、用户多久没动

        ↓ 汇成一个「行为状态」 behavior

行为状态（9 种，互斥）
├─ sleeping   睡着        deep night + 长时间无活动
├─ drowsy     困倦        深夜 / energy 低
├─ idle       发呆        默认
├─ curious    好奇        鼠标靠近 / 有新东西出现
├─ focused    专注        有任务在跑
├─ worried    不安        有任务卡住或失败
├─ pleased    得意        任务成功 / 被夸
├─ sulky      闹脾气      被戳太多次 / 被冷落
└─ clingy     黏人        好感度高 + 用户刚回来

        ↓ 每个状态决定

动作池 + 动作频率 + 表情池 + 台词池 + 注意力方向
```

**核心变化：动作不再随机抽，而是「这个状态下它想做什么」。**

## 三、第一步：给动作打标签

`pet-actions.js` 现在每条是 `[group, id, effect, animation, duration]`。补两项：这个动作**什么情绪下会做**、**属于什么行为意图**。

```js
// 每条：[group, id, effect, animation, duration, moods, intents]
// moods 空数组 = 任何情绪都合适
// intents: celebrate / withdraw / inspect / settle / panic / seek
const ACTIONS = [
  ['head', 'hat-check',   'sweat', 'hatCheck',   900, [],                    ['inspect']],
  ['head', 'soft-lean',   'heart', 'softLean',   980, ['开心', '兴奋'],       ['seek']],
  ['head', 'proud-bow',   'star',  'proudBow',  1080, ['得意'],               ['celebrate']],
  ['face', 'double-blink','star',  'doubleBlink',620, [],                     ['settle']],
  ['face', 'look-away',   'question','lookAway', 760, ['委屈', '有点烦', '闹别扭'], ['withdraw']],
  ['face', 'startle',     'exclaim','startle',   540, ['犯困', '平静'],        ['panic']],
  ['body', 'jelly-bounce','note',  'jellyBounce', 840, ['开心', '兴奋'],       ['celebrate']],
  ['body', 'side-brace',  'sweat', 'sideBrace',  760, ['有点烦', '闹别扭'],    ['withdraw']],
  ['body', 'cape-flick',  'dust',  'capeFlick',  980, ['得意'],               ['celebrate']],
  ['feet', 'quick-hop',   'dust',  'quickHop',   720, ['兴奋'],               ['celebrate']],
  ['feet', 'stumble',     'exclaim','stumble',   680, ['委屈', '犯困'],        ['panic']],
  ['feet', 'heel-tap',    'note',  'heelTap',    900, ['有点烦'],             ['settle']],
  ['idle', 'slow-yawn',   'ellipsis','slowYawn', 1250, ['犯困'],              ['settle']],
  ['playful','cheer',     'star',  'cheer',      980, ['开心', '兴奋'],        ['celebrate']],
  ['magic','sparkle-cast','heart', 'sparkleCast', 920, ['开心', '兴奋'],       ['celebrate']]
];
```

**注意：`moods` 不是硬限制，是权重。** 情绪匹配的动作权重 ×3，不匹配的 ×0.2（不是 0，生物偶尔也会有反常举动，但很少）。

## 四、第二步：行为状态机

新增 `renderer/behavior.js`（渲染层，因为它要读鼠标、要管动作节奏）：

```js
// 9 种行为状态，互斥。每 1 秒评估一次该进哪个状态。
function evaluateBehavior({ emotion, affection, energy, idleMs, mouseNear, queue, irritability }) {
  const blocked = (queue?.blocked || 0) > 0;
  const running = (queue?.running || 0) > 0;
  const review = (queue?.review || 0) > 0;

  // 优先级从高到低，先命中先返回
  if (energy < 0.12 && idleMs > 120000) return 'sleeping';
  if (irritability >= 3) return 'sulky';
  if (blocked) return 'worried';
  if (energy < 0.3) return 'drowsy';
  if (review) return 'pleased';            // 有东西等验收，它先高兴一下
  if (running) return 'focused';
  if (mouseNear && affection >= 60) return 'clingy';
  if (mouseNear) return 'curious';
  if (idleMs > 600000 && affection >= 70) return 'clingy';
  return 'idle';
}
```

**每个状态配一张表**（频率 = 多久做一个动作，ms）：

| 状态 | 动作间隔 | 动作倾向 | 表情 | 是否跟随鼠标 |
|---|---|---|---|---|
| `sleeping` | 不动作 | 只有呼吸 | `sleepy` | 否 |
| `drowsy` | 9000~16000 | `settle` 为主（打哈欠、点头） | `sleepy` | 弱 |
| `idle` | 3500~8000 | 均衡 | 跟情绪 | 是 |
| `curious` | 2200~5000 | `inspect` / `settle` | 跟情绪 | 强（转头看） |
| `focused` | 5000~9000 | 少动，`settle` 占多数 | `thinking` | 弱 |
| `worried` | 1800~3200 | `panic` / `withdraw` | 跟情绪 | 是 |
| `pleased` | 1500~3000 | `celebrate` | `happy` | 是 |
| `sulky` | 4000~7000 | `withdraw` 为主，不主动靠近 | 跟情绪 | **否**（不理你） |
| `clingy` | 2000~4500 | `seek` / `settle` | `happy` | 强 |

`sleeping` 和 `sulky` 都「不跟鼠标」——**这是关键**，生物会赌气。

## 五、第三步：精力节律

`pet-state.js` 加一个 `energy`（0~1），按小时算基础值：

```js
// 生物不是 24 小时一个样。凌晨该困，上午最精神，午饭后犯困，晚上又起来。
function energyAt(hour) {
  if (hour >= 1 && hour < 6) return 0.15;
  if (hour < 8)  return 0.35;   // 天快亮，慢慢醒
  if (hour < 11) return 0.95;   // 上午最精神
  if (hour < 14) return 0.55;   // 午饭后犯困
  if (hour < 18) return 0.85;
  if (hour < 22) return 1.0;    // 晚上是它的高峰
  return 0.45;
}
```

再叠加「隔了多久才见面」：

```js
// 隔了一夜没见，精力回满；隔了三天没见，反而没劲（生物会生疏）
const hoursAway = (Date.now() - (saved.lastSeen || Date.now())) / 3600000;
const recovery = hoursAway > 20 ? 1.0 : hoursAway > 8 ? 0.85 : 0.9;
```

**`energy` 影响两件事**：动作频率（低精力 → 间隔拉长）、动作幅度（低精力 → 幅度 ×0.7，看起来没劲）。

## 六、第四步：行为链（这是「生物感」最强的一条）

现在戳一下 = 播一段动作。生物不会这样，生物的反应是分段的：

```js
// 一段反应有多拍，每拍自己的动作和延迟
const CHAINS = {
  // 被戳第 1 下：吓一下，然后偷看，最后放松
  pokedFirst: [
    { intent: 'panic',    delay: 0 },
    { intent: 'inspect',  delay: 480 },
    { intent: 'settle',   delay: 420 }
  ],
  // 连戳第 3 下：先闹脾气，再背过去，最后忍不住回头看
  pokedRepeated: [
    { intent: 'withdraw', delay: 0 },
    { intent: 'withdraw', delay: 520 },
    { intent: 'inspect',  delay: 800 }
  ],
  // 任务成功：欢呼 → 鞠躬 → 稳定
  taskDone: [
    { intent: 'celebrate', delay: 0 },
    { intent: 'celebrate', delay: 700 },
    { intent: 'settle',    delay: 600 }
  ],
  // 任务卡住：不安 → 张望 → 不安
  taskBlocked: [
    { intent: 'panic',   delay: 0 },
    { intent: 'inspect', delay: 620 },
    { intent: 'panic',   delay: 560 }
  ]
};
```

```js
let chainTimers = [];
function runChain(name) {
  chainTimers.forEach(clearTimeout);
  chainTimers = [];
  let t = 0;
  for (const step of CHAINS[name] || []) {
    t += step.delay;
    chainTimers.push(setTimeout(() => playActionByIntent(step.intent), t));
  }
}
```

**「连戳第 3 下」那一段最后一下 `inspect`（忍不住回头看）是生物感的关键**——闹脾气但好奇，这一下就有了性格。

## 七、注意力：它在看哪儿

现在只有鼠标驱动 `--look-x/--look-y`。加一个「注意力目标」：

```js
let attention = 'mouse';   // mouse | task | user | none

// curious/clingy → mouse
// focused/worried → task（看向状态药丸的方向，偏移固定）
// sulky → none（视线偏开 30%）
// pleased → user（看向气泡）
```

`none` 的时候视线不跟鼠标，而是缓慢漂移（模拟走神）：

```js
// 走神时视线慢慢晃，不是死盯一点
if (attention === 'none') {
  const t = Date.now() / 3400;
  lookX = Math.sin(t) * 0.6;
  lookY = Math.cos(t * 0.7) * 0.3;
}
```

**走神是「活着」的强信号**——机器不会走神。

## 八、实现顺序（四步，每步独立可验）

### 第 1 步：动作打标签 + 情绪加权
改 `pet-actions.js` 加 `moods`/`intents`，`chooseAction` 改成按权重抽。**这一步做完，闹别扭时就不会欢呼了。**

验收：强制把情绪设成「闹别扭」，点身体 10 次，抽到的动作里不能出现 `jelly-bounce`/`cheer`/`proud-bow`。

### 第 2 步：精力节律
`pet-state.js` 加 `energy`，`renderer/pet.js` 的动作间隔按 energy 缩放。

验收：把系统时间改成凌晨 3 点（或者把 `energyAt` 的入参临时改死），动作间隔要明显变长、幅度变小。

### 第 3 步：行为状态机
新增 `renderer/behavior.js`，每 1 秒评估一次，状态影响动作间隔和动作池。

验收：造一个 `blocked` 任务，它要进 `worried`——动作变频繁、偏向 `panic`；把好感度设 20、连戳 4 次，要进 `sulky`——**视线明显不跟鼠标了**。

### 第 4 步：行为链 + 注意力
第 3 步稳了再做这一步。行为链改的是点击处理路径，注意力改的是视线。

验收：连戳 3 下有「缩→背过去→回头看」三段；在 `sulky` 状态下鼠标划过，视线要偏开。

---

## 九、不许做的

1. **不要让情绪变成硬门槛**（`moods` 不匹配就 0 概率）。生物会反常，留 0.2 的权重
2. **不要在 `sulky` 状态下还让它主动说话**。赌气就要赌气到底，2 分钟内不主动开口
3. **行为链的总时长控制在 2.5 秒内**。超过就成过场动画了
4. **`sleeping` 状态不要被点击唤醒得太快**。睡着的生物被戳要「先动一下、再醒」，不能秒回 `idle`
5. **别把 energy 写死成常量**。它的价值在于「一天里不一样」

## 十、验收的最终判据

不看代码，看行为。观察 5 分钟，能回答出这三件事就算成了：

1. **它现在是什么状态？**（能说出来：在打哈欠 / 在盯着我 / 在闹脾气 / 在偷看任务）
2. **它为什么是这个状态？**（因为我刚戳了它三次 / 因为有活卡住了）
3. **下一秒它大概会做什么？**（大概率继续闹脾气，小概率忍不住看我一眼）

**答不出这三条，说明还是在随机播动作。** 这三条是「生物」和「动画播放器」的唯一区别。

汇报时不要写「动态感增强了」，写：5 分钟里观察到的状态序列，以及每次状态切换是由什么触发的。
