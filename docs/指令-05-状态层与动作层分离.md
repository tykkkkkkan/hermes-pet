## 二、必修（P1）：状态动画和动作动画还是一个元素在抢

### 现象

`renderer/pet.js:248-252`，五个状态 class 全加在 `gestureEl` 上：

```js
gestureEl.classList.toggle('thinking', s.status === 'thinking');
gestureEl.classList.toggle('working',  s.status === 'working');
gestureEl.classList.toggle('success',  s.status === 'success');
gestureEl.classList.toggle('error',    s.status === 'error');
gestureEl.classList.toggle('sleep',    s.status === 'sleep');
```

`renderer/style.css:211-217`，这些状态本身是动画：

```css
#pet-gesture.working { animation: work 1.5s ease-in-out infinite; filter: ...; }
#pet-gesture.error   { animation: error 0.9s ease-in-out infinite; filter: ...; }
```

`renderer/pet.js:375` 又把 `gesture-active` 加到同一个元素：

```js
gestureEl.classList.add('gesture-active');
```

也就是说：**呼吸那一层的冲突修掉了，但状态层和动作层的冲突原样还在，只是从 `#pet` 挪到了 `#pet-gesture`。**

### 为什么这次比上次更隐蔽

`#pet-gesture.gesture-active[data-action="jelly-bounce"]` 的特异性是 `(0,3,0)`，高于 `#pet-gesture.working` 的 `(0,2,0)`，所以：

| 属性 | `working`（简写，0,2,0） | `gesture-active`（0,3,0 或同特异性靠后） | 实际生效 |
|---|---|---|---|
| `animation-name` | `work` | `jellyBounce` | `jellyBounce` |
| `animation-duration` | `1.5s` | `calc(var(--gesture-ms) * 1ms)` | `calc(...)` |
| `animation-timing-function` | `ease-in-out` | `cubic-bezier(.34,1.56,.64,1)` | `cubic-bezier(...)` |
| `animation-iteration-count` | `infinite` | **没设** | **`infinite` 残留** |

最后一行是坑：`gesture-active` 那一组规则只写了 `animation-name` / `animation-duration` / `animation-timing-function`（`style.css:273-288`），没写 `animation-iteration-count`。而 `#pet-gesture.working` 的 `animation` 简写里带 `infinite`——这个值**不会被清掉**。

结果：Hermes 正在执行任务时点它，播的是一个**无限循环的 `jellyBounce`**，靠 `setTimeout` 硬掐 1 秒多才停。肉眼是"抽个不停然后突然停"，不是设计里的一次弹跳。

同理 `error`（0.9s infinite）、`thinking`（1.1s infinite）、`sleep`（4.5s infinite）被点击时都会这样。`success`（0.8s ease-out）非无限，但 `gesture-active` 移除后 class 还在，`success` 会**从 0% 重播一次**。

`drowsy`（闲置 20 分钟后的困倦摇摆，4.5s infinite）也会被顶掉。这个相对可接受——用户一点它就醒本来就对（`pet.js:401-404` 有 `mouseenter` 清 `drowsy`），不用特意处理。

### 改法：状态层再拆一层

四层各管一条 transform，永不同元素抢：

```text
#pet            breathe（常驻）          ← 已有，动画在 .pet-layer 上，别动
  #pet-state    状态动画（thinking/working/error/sleep/success）  ← 新增
    #pet-gesture  动作动画（gesture-active）  ← 已有
      #pet-inner   视线偏移（--look-x/--look-y）  ← 已有，别动
```

`renderer/index.html:25-33` 改成：

```html
<div id="pet" aria-label="赫尔墨兹桌宠">
  <div id="pet-live2d-host"></div>
  <div id="pet-state">
    <div id="pet-gesture">
      <div id="pet-inner"> ... 图层 ... </div>
    </div>
  </div>
  <div id="pet-hit-area" aria-hidden="true"></div>
  <div id="pet-fx" aria-hidden="true"></div>
</div>
```

```css
#pet-state,
#pet-gesture {
  position: absolute;
  inset: 0;
  transform-origin: 50% 96%;
}
```

`style.css:208-225` 那批 `#pet-gesture.hop / .thinking / .working / .success / .error / .sleep / .drowsy / .squish / .stretch` 全部换成 `#pet-state.*`。
`style.css:143-149` 的 `body[data-live2d="on"]` 选择器同步换。

`renderer/pet.js` 里维护一个 `stateEl = document.getElementById('pet-state')`：

- `paintState` 的五个 `gestureEl.classList.toggle(...)` → `stateEl.classList.toggle(...)`
- `pet.js:399` 的 `gestureEl.classList.toggle('drowsy', ...)` → `stateEl`
- `pet.js:403` 的 `gestureEl.classList.remove('drowsy')` → `stateEl`
- 其余 `.hop / .squish / .stretch` 的挂载点（打回原形的）同样搬到 `stateEl`
- `gestureEl` 只保留 `gesture-active` 和 `data-action`，**一个状态 class 都不留**

改完自查这一条：在 `pet.js` 里搜 `gestureEl`，除了 `dataset.action`、`--gesture-ms`、`gesture-active`、`animationend` 相关，不该出现任何状态名。

### 顺带补一个保险

`#pet-gesture.gesture-active`（`style.css:273`）显式写死 iteration count，别依赖继承：

```css
#pet-gesture.gesture-active {
  animation-duration: calc(var(--gesture-ms, 900) * 1ms);
  animation-iteration-count: 1;
  animation-fill-mode: both;
}
```

就算将来又有人把状态动画挂回同一层，也不会变成无限循环。

## 四、要修（P2）：待机只剩 3 个动作，重复率会很明显

`renderer/pet.js:384-393`

```js
const group = ['idle', 'idle', 'playful', 'magic'][Math.floor(Math.random() * 4)];
```

`pet-actions.js` 里 `idle` / `playful` / `magic` 三组**各只有一个动作**：`slowYawn`、`cheer`、`sparkleCast`。间隔 6~13 秒，一次播 1 秒左右——**待机状态下三分钟就能把全部 3 个动作看完一遍**，之后开始循环复读。

而用户 95% 的时间看的就是待机。15 个动作里 12 个要主动点击才出现，待机体验实际只有 3 个。

**改法（已定：A，用户 2026-10-28 拍板）**：

- **A（执行这条）**：`idleLoop` 从全部 15 个动作里随机挑，不再只限 `idle/playful/magic` 三组。桌宠本来就会自己动，头/脸/身/脚那 12 个动作当作它自己活动也成立。改一个数组即可，成本最低
- B（不做）：给 `idle` / `playful` / `magic` 各补 2~3 个真动作，扩到 21~24 个。要画新关键帧，收益与 A 重叠——A 已经把 15 个全用上了
- C（不做）：保住 3 个，把待机间隔从 6~13 秒拉长到 20~40 秒。治标，动作多样性没解决

具体改法：

```js
// pet.js:384-393
// 待机不再只播三组，15 个动作全部参与；桌宠自己活动起来才像个活物
function idleLoop() {
  const wait = 6000 + Math.random() * 7000;
  setTimeout(() => {
    if (!dragging && !bubbleVisible() && (petEl.dataset.state || 'idle') === 'idle') {
      playAction('any');
    }
    idleLoop();
  }, wait);
}
```

`pet-actions.js` 的 `chooseAction` 加一个 `'any'` 分支，命中全部 15 个：

```js
function chooseAction(group, previousId = '', random = Math.random) {
  const pool = group === 'any'
    ? ACTIONS
    : ACTIONS.filter((action) => action.group === group);
  if (!pool.length) return null;
  const candidates = pool.length > 1 ? pool.filter((action) => action.id !== previousId) : pool;
  return candidates[Math.floor(random() * candidates.length)] || pool[0];
}
```

现有 `chooseAction` 已经排除 `previousId`，防连续复读够用，不用另加逻辑。
`test/pet-actions.test.js` 补一条：`chooseAction('any')` 返回值非空，且连续两次不重复。
