## 二、改法

### 1. `main.js`：传精简列表，别整包传

状态是高频推送的，把几十条任务原样过 IPC 不划算。只传面板要显示的那几个字段，并且分组截断。

在 `main.js` 里 `taskTitle` 附近加：

```js
// 面板一次最多显示这么多条，避免窗口里堆成瀑布
const PANEL_MAX_PER_GROUP = 5;
const slimTask = (task) => ({
  id: task.id ?? '',
  title: taskTitle(task),
  assignee: task.assignee || '',
  status: task.status || ''
});
const slimGroup = (list) => (Array.isArray(list) ? list.slice(0, PANEL_MAX_PER_GROUP).map(slimTask) : []);
```

`petState` 那处补一个 `tasks` 字段（`currentTask` 保留不动，播报逻辑在用）：

```js
const allTasks = Array.isArray(next.tasks) ? next.tasks : [];
const queued = allTasks.filter((t) => ['todo', 'ready', 'scheduled'].includes(t.status));
tasks: {
  running: slimGroup(next.running),
  blocked: slimGroup(next.blocked),
  review: slimGroup(next.review),
  queued: slimGroup(queued),
  total: allTasks.length
}
```

`petState` 的初始值（`main.js:40-53`）也要补一个空结构，否则第一次推送前 `paintState` 读不到：

```js
tasks: { running: [], blocked: [], review: [], queued: [], total: 0 },
```

### 2. `renderer/index.html`：面板加列表容器

`#panel-tasks` 放在最下面，四组列表都往这里画。

### 3. `renderer/pet.js`：只在数据变了才重建

**这条是最容易做错的地方。** 现在 `panelAgents.innerHTML = ...` 是每次 `paintState` 都重建，而状态推送可能一秒来好几次。列表要是也这么写，会闪、hover 会丢、滚动位置会跳。

加一个变化判断，没变就别碰 DOM：

```js
let lastTasksJson = '';
function paintTaskLists(tasks) {
  const json = JSON.stringify(tasks || {});
  if (json === lastTasksJson) return;   // 数据没变，一个 DOM 都不动
  lastTasksJson = json;

  const groups = [
    ['running', '执行中'],
    ['blocked', '受阻'],
    ['review', '待验收'],
    ['queued', '排队']
  ];
  const html = groups.map(([key, label]) => {
    const list = Array.isArray(tasks?.[key]) ? tasks[key] : [];
    if (!list.length) return '';
    const items = list.map((t) => {
      const who = t.assignee ? `<span class="t-who">${escapeHtml(t.assignee)}</span>` : '';
      return `<li>${escapeHtml(t.title)}${who}</li>`;
    }).join('');
    return `<div class="t-group"><div class="t-head">${label} <b>${list.length}</b></div><ul>${items}</ul></div>`;
  }).join('');

  // 四组全空时给一句人话，别留一块空白
  tasksEl.innerHTML = html || '<div class="t-empty">看板是空的，暂时没活派给我</div>';
}
```

`escapeHtml` 如果 `renderer/pet.js` 里没有就补一个（任务标题来自 Hermes，不能直接拼进 innerHTML）：

```js
const escapeHtml = (text) => String(text ?? '').replace(/[&<>"']/g, (c) => ({
  '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;'
}[c]));
```

`panelAgents` 也顺手改成同样的"变了才动"逻辑，现在它每次重建，Agent 那块一直在闪。

在 `paintState` 里 `panelAgents.innerHTML = ...` 那行附近调用 `paintTaskLists(s.tasks)`。

### 3. 任务失败播报只覆盖 `blocked`

`main.js` 里失败播报现在只认 `blocked`。有了 `next.tasks` 之后，可以按状态细分：

| 状态 | 播报 |
|---|---|
| `blocked` | 「卡住了」——需要人介入 |
| `error` / `failed` | 「失败了」——自动重试或放弃 |
| `review` | 「做完了，等你验收」——不是失败 |

现在 `error` 混在别的地方或者根本不播。改成三条分开，`review` 单独一条。注意别把 `review` 当失败播，那会让桌宠每次交付都摆一副出事的样子。

## 五、验收

### 仪表盘

1. 面板展开，四组（执行中 / 受阻 / 待验收 / 排队）都正确显示，每组最多 5 条，底部显示总数
2. **看板为空时**显示「看板是空的，暂时没活派给我」，不能是空白一块
3. **连续观察 30 秒不闪**：状态在推送，但列表内容没变时 DOM 不能重建。验法：在 DevTools 里给 `#panel-tasks` 挂 `MutationObserver` 数变更次数，30 秒内应该是 0 次（除非真的有任务状态变化）
4. 有一批长标题任务时，列表单行省略号截断，不能撑破面板宽度
5. 任务多于 5 条时面板内部滚动，滚动条是 4px 细的，不出现系统粗滚动条
6. 面板打开着，后台任务状态变化 → 列表原地更新，**面板不自动收起**
7. Hermes 离线 → 计数归零、列表清空/空态，不报错、不显示 NaN

### 顺手三件

8. README 路线图那一行已打勾，「已知未做」少了热区复核那条
9. 造三个任务分别进 `blocked` / 失败态 / `review`，播报文案要三条不同，`review` 不能报成失败
