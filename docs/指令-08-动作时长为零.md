# 指令 08 · 15 个动作的动画时长是 0，从来没播过

> 这是目前最严重的问题，也是最容易被"测试全绿"掩盖的问题：从 `aec860f` 引入动作表到现在，**没有一个动作动画真正播放过**。
> 下面每条都有实测输出，不是推断。

---

## 一、结论

```css
/* renderer/style.css:282-286 */
#pet-gesture.gesture-active {
  animation-duration: calc(var(--gesture-ms, 900) * 1ms);
  animation-iteration-count: 1;
  animation-fill-mode: both;
}
```

这条规则在这台机器上**求值失败，回落成 `0s`**。0 秒的动画等于没有动画。

所以用户点桌宠时看到的是：`#pet-state` 的 `hop`（那条是字面量 `animation: hop 0.5s`，有效）+ 粒子特效（有效）+ **身子完全不动**。

`pet-actions.js` 里 15 个动作的 duration、15 段 `@keyframes`、15 条 `animation-name` 映射，全部白写。

---

## 二、实测证据

用 CDP 进渲染进程直接读计算样式。`--gesture-ms` 已经设成 900 的前提下：

```text
setProperty(数字900)               {"var":"900","dur":"0s","name":"heelTap"}
setProperty(字符串"900")            {"var":"900","dur":"0s","name":"heelTap"}
内联 animationDuration=900ms       {"var":"900","dur":"0.9s","name":"heelTap"}   ← 有效
setProperty("900ms")               {"var":"900ms","dur":"0s","name":"heelTap"}
移除变量用默认900                    {"var":"","dur":"0s","name":"heelTap"}
字面量 calc(900 * 1ms)              {"dur":"calc(0.9s)"}                        ← 有效
字面量 calc(1ms * 900)              {"dur":"calc(0.9s)"}                        ← 有效
```

`animation-name` 一直是 `heelTap`（说明选择器和 `data-action` 都对，动作确实被选中了），**只有 duration 是 0s**。

也就是说：`calc()` 本身没问题、`var()` 单独用没问题、字面量乘时间没问题，**唯独 `calc(var(--x) * 1ms)` 这个组合求值失败**。

这不是 `prefers-reduced-motion` 降级——我测过 `matchMedia('(prefers-reduced-motion: reduce)').matches === false`。

### 行为层面的旁证

**待机 42 秒**（不点击，只观察 `#pet-gesture` 的 `dataset.action` 和 class，50ms 轮询）：

```text
   0.1s  动作=无              class=                             气泡=hide 状态=idle
   7.1s  动作=soft-lean      class=gesture-active               气泡=hide 状态=idle
   7.2s  动作=无              class=                             气泡=hide 状态=idle
  37.2s  动作=soft-lean      class=gesture-active               气泡=hide 状态=idle
  37.3s  动作=无              class=                             气泡=hide 状态=idle
```

动作 class 只存在 **100 毫秒以内**——50ms 轮询只可能抓到一帧。980ms 的 `softLean` 应该占据近 1 秒。

**四区各连点三次**（每次点完等 900ms 再读）：

```text
[head]
  1. 行，摸完记得说正事        动作=无  duration=0s  name=none
  2. 好大爹这是来验收的吧       动作=无  duration=0s  name=none
  3. 困着呢，摸头也不提神       动作=无  duration=0s  name=none
[face] / [body] / [feet]       同样 12 次全部 动作=无 duration=0s
```

12 次点击，`animationName` 已经回落到 `none`，`duration` 始终 `0s`。

## 三、为什么 smoke 全绿却没抓到

现在这几条断言全部成立：

```js
gesture.classList.contains('gesture-active') === true     // class 确实加了
getComputedStyle(gesture).animationIterationCount === '1' // iteration 确实是 1
gesture.dataset.action === 'soft-lean'                    // data-action 确实设了
```

**`iteration-count: 1` 对一个 0 秒动画同样成立。** 断言的是"配置对不对"，不是"动画跑没跑"。

判断一个动画是否真的发生，只有两个可靠指标：

1. `getComputedStyle(el).animationDuration` **不是** `0s`
2. 动画期间元素的 `transform` / `getBoundingClientRect()` **真的发生了变化**

第二条最硬。第一条能立刻抓到这个 bug。

## 四、改法

### 主修：时长由 JS 内联写，CSS 不参与计算

`renderer/pet.js` 的 `playAction`：

```js
function playAction(group) {
  const action = window.pet.chooseAction?.(group, lastActionId);
  if (!action) return;
  clearGesture();
  lastActionId = action.id;
  gestureEl.dataset.action = action.id;
  // 时长直接写内联。CSS 里的 calc(var(--gesture-ms) * 1ms) 在本机求值成 0s，
  // 动作从来没播过；内联 '900ms' 是实测有效的写法。
  gestureEl.style.animationDuration = `${action.duration}ms`;
  void gestureEl.offsetWidth;
  gestureEl.classList.add('gesture-active');
  ...
}
```

`style.css:282-286` 删掉 `animation-duration` 那一行，只留：

```css
#pet-gesture.gesture-active {
  animation-iteration-count: 1;
  animation-fill-mode: both;
}
```

`clearGesture()` 里补一句清掉内联值，否则下一次如果忘了设，会沿用上次的时长：

```js
function clearGesture() {
  if (gestureAnimationHandler) gestureEl.removeEventListener('animationend', gestureAnimationHandler);
  gestureAnimationHandler = null;
  clearTimeout(gestureTimer);
  gestureEl.classList.remove('gesture-active');
  delete gestureEl.dataset.action;
  gestureEl.style.removeProperty('animation-duration');   // 新增
}
```

`--gesture-ms` 这个变量可以整个删掉（`pet.js:374` 的 `setProperty` 和 CSS 里的 `var()` 一起清），留着一个用不上的变量，下次有人又照着它写一遍 `calc()`。

### 备选：如果坚持用 CSS 变量

把值本身带上单位，别在 CSS 里乘：

```js
gestureEl.style.setProperty('--gesture-ms', `${action.duration}ms`);
```
```css
#pet-gesture.gesture-active { animation-duration: var(--gesture-ms, 900ms); }
```

我实测过 `var(--gesture-ms, 900ms)` 这条路径**没有验证过**（只验了内联 `animationDuration` 有效），所以推荐主修方案，别赌。

## 五、必须补的测试（不补的话下次还会瞎）

### 1. 断言时长非零

在 smoke 的动作检查里加：

```js
const dur = getComputedStyle(gesture).animationDuration;
check('动作时长为非零', dur !== '0s' && parseFloat(dur) > 0.1, `duration=${dur}`);
```

现在 `点头动作单次播放且不抢呼吸` 那条的 detail 里已经有 `animation: "none"`——**`animation: none` 本身就是失败信号**，可惜断言只看了 `iteration`。

### 2. 断言元素真的动了（这条最关键）

动作开始后间隔 150ms 取两次 `getBoundingClientRect()`，位置必须有变化：

```js
const p1 = gesture.getBoundingClientRect();
await new Promise(r => setTimeout(r, 150));
const p2 = gesture.getBoundingClientRect();
const moved = Math.abs(p1.top - p2.top) + Math.abs(p1.left - p2.left) > 0.5;
check('动作真的产生了位移', moved, `Δtop=${(p2.top-p1.top).toFixed(2)} Δleft=${(p2.left-p1.left).toFixed(2)}`);
```

注意要在动作开始后的 150~400ms 之间取，太晚会因为 `animation-fill-mode: both` 回到终态而看不出位移。取 `--gesture-ms` 的一半左右最稳。

### 3. 15 个动作逐个过

现在只测了 head 和 feet 各一个。改成循环 15 个，每个都验"duration 非零 + 有位移"，任何一个不过就红。这才是"15 个动作"这个说法该有的测试强度。

## 七、验收

修完必须给这几样，缺一样都不算完：

1. **15 个动作逐个的 `animationDuration`**，一条一行打出来，不能有 `0s`
2. **15 个动作逐个的位移量**（Δtop / Δleft），不能有 `0.00`
3. 待机 42 秒的动作序列，每次动作的 class 存在时长要接近它声明的时长（±100ms），不能再是 100ms
4. `npm test` → `pass N / fail N`
5. `npm run smoke -- --isolated` → `pass N / fail N`
6. 截图：动作播放中截一张（不是动作结束后截），要能看出身子确实歪了/跳了

第 3 条是这次的核心判据。**动作 class 存在时长 ≈ 声明时长**，才说明动画真的在播。
