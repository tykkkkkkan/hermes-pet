# 指令 11 · 拆 main.js（第一步：地基）

> 接下来不加新功能，只补地基。这份是第一份，目标是把 1377 行的 `main.js` 拆成几个能单独测的模块。
> **这是重构，不是改行为。** 渲染层、IPC 通道名、用户能看到的东西，一律不动。

---

## 一、为什么拆

```text
main.js                 1377 行   50 个顶层函数   35 个 IPC handler   0 个单测
renderer/pet.js          597 行
renderer/chat.js         649 行
pet-actions.js            31 行   ← 有测试
pet-interactions.js       40 行   ← 有测试
pet-emotion.js            85 行   ← 有测试
pet-runtime.js            71 行   ← 有测试
pet-faces.js              51 行   ← 有测试
pet-regions.js            28 行   ← 有测试
```

规律很清楚：**拆出来的模块都有测试，没拆的一行都没有。** 而已知的关键 bug 全在没拆的那部分：

- `prompt.submit` 405（`hermes-bridge.js` / `hermes-chat.js` 交接处）
- 动作动画 0 秒（`style.css` 的 calc，但触发链路全在 `main.js` 的 `playAction` 调用方）
- 情绪表情 5 种空转（`preload.js` 和 `renderer/pet.js` 的映射表脱节）
- 呼吸被动作顶掉（`renderer/pet.js` 和 `style.css` 的层叠）

这不是 Codex 水平问题，是**一个文件里同时装着状态、服务器、轮询、密钥、窗口**，改任何一处都摸不清波及面。

目标：`main.js` 从 1377 行降到 300 行左右，只留窗口、菜单、托盘、IPC 转接。其余搬出去，各自有单测。

## 二、拆成什么

```text
main.js                 壳：app 生命周期、窗口、菜单、托盘、IPC 转接
settings-store.js       设置读写、密钥加解密、从 Hermes 导入 key
pet-speech.js           台词格式化（prepareUtterance）、称呼轮换
pet-state.js            情绪/好感/心情/称呼/地址历史 + 持久化
bridge-server.js        HTTP 桥接服务器 + token 鉴权
hermes-poller.js        3 秒轮询、快照映射、状态边沿检测
```

### 依赖方向（必须单向，否则拆了等于没拆）

```text
main.js
  ├─→ settings-store     （无依赖，只依赖 fs 和 safeStorage）
  ├─→ pet-speech         （依赖 persona 数据，纯函数）
  ├─→ pet-state          （依赖 pet-emotion、pet-speech）
  ├─→ hermes-poller      （依赖 hermes-bridge、pet-state）
  └─→ bridge-server      （依赖 pet-state、hermes-bridge，通过注入拿 announce）
```

**`pet-state` 绝不能 require `hermes-poller`**，反之才可以。如果拆的时候发现绕不过去，说明职责划错了，停下来先调整边界，别用 require 互相拉扯。

### 依赖注入约定（这条决定能不能单测）

不要在这些新模块里 `require('./main')` 或者直接摸 `win`。所有外部能力走参数传进去：

```js
// main.js 里这样装配
const settingsStore = require('./settings-store')({ dataDir, safeStorage, hermesDir: HERMES_DIR });
const speech = require('./pet-speech')({ persona });
const petState = require('./pet-state')({
  emotion: petEmotion,
  speech,
  settingsStore,
  onChange: (state) => pushPetState(state)
});
const poller = require('./hermes-poller')({
  bridge: hermesBridge,
  state: petState,
  announce: (text, options) => announce(text, options)
});
const bridgeServer = require('./bridge-server')({
  state: petState,
  bridge: hermesBridge,
  announce: (text, options) => announce(text, options),
  bridgeFile
});
```

外置模块的形态统一成「工厂函数返回对象」：

```js
module.exports = function createSettingsStore(deps) {
  let cache = null;
  function load() { ... }
  function save(input) { ... }
  return { load, save, getApiKey, importFromHermes, publicView };
};
```

这样单测里传假 `dataDir`（临时目录）、假 `safeStorage`（直接返回明文）、假 `announce`（记下调用参数）就能测，不用起 Electron。

## 三、分五步走，每步一个提交

**不要一口气拆完。** 每步都要做到：`npm test` 全绿 + `npm run smoke -- --isolated` 21/21，然后再下一步。中途任何一步不过，就停在那里修，不要往后叠。

### 第 1 步：`settings-store.js`（最独立，先拿它练手）

搬走这些函数：`dataDir`、`readJson`、`writeJson`、`settingsFile`、`historyFile`、`loadSettings`、`saveSettings`、`getApiKey`、`importKeyFromHermes`、`publicSettings`（`main.js:87-98`、`426-566` 一带）。

**注意 `writeJson` 现在已经是 tmp + rename 的原子写**（`main.js:426-437`），保留这个做法，别改成直接 `writeFileSync`。

新增 `test/settings-store.test.js`，至少覆盖：

1. 文件不存在时 `load()` 返回默认值，不抛
2. 文件内容是坏 JSON 时 `load()` 返回默认值，不抛（这是我现在不确定有没有保护的地方，拆的时候顺手确认）
3. `save({ petScale: 999 })` 后 scale 被夹到 70~140
4. `getApiKey()` 在没存 key 时返回空字符串，不抛
5. 明文 key 落盘后读回来能解密（假 `safeStorage` 下）

### 第 2 步：`pet-speech.js`

搬走 `prepareUtterance`（`main.js:197-218`）和称呼轮换逻辑（现在依赖 `petState.address` / `addressHistory`，改成纯参数）。

签名改成：

```js
// 纯函数：输入台词模板、当前称呼、可用称呼池、历史，输出最终文本
function prepareUtterance(text, { address, pool, history, keepAddress, chooseAddress })
```

`announce` 本身留在壳里（它要用 `win.webContents.send` 和 `Notification`），但它内部改成调 `speech.format(...)`。

新增 `test/pet-speech.test.js`：

1. `{address}` 占位符被替换
2. 文本开头已有称呼时不重复加
3. `keepAddress: true` 时称呼不变（互动台词用这个，连点几下不能换名字）
4. 称呼池为空时回落「好大爹」

### 第 3 步：`pet-state.js`

搬走：`petState` 变量本身、`emptyTaskPanel`、`applyEmotionEvent`、`refreshEmotionClock`、`trackUserEmotion`、`loadPetState`、`savePetState`、`adjustPetState`、`setPetState`、`pushPetState`、`PANEL_MAX_PER_GROUP` 那套任务面板打包（`slimTask`/`slimGroup`/`packTaskGroup`/`buildTaskPanel`）。

```js
{

  set(patch),               // 合并字段

  trackUserText(text),      // 从用户输入里读情绪

```

新增 `test/pet-state.test.js`：

1. `affection` / `mood` 夹在 0~100
2. `applyEmotion('success')` 后 mood 涨、affection 涨，且不超过上限
3. 时间衰减：跨 1 小时回落，未满 1 小时不衰减（`pet-emotion.js` 已有类似测试，这里测集成）
4. `buildTaskPanel` 传 6 条 running → `items.length === 3`、`total === 6`
5. `load()` 读坏文件时回落默认状态，不抛

### 第 4 步：`bridge-server.js`

搬走：`bridgeFile`、`bridgeJson`、`bridgeAuthorized`、`readBridgeBody`、`bridgeState`、`startBridgeServer`、`stopBridgeServer`（`main.js:219-348`）。

**这块动的时候格外小心**：35 个 IPC 里没有它，但 Hermes 插件是通过这个 HTTP 服务读状态、派任务的，`hermes-pet` 插件对外 6 个工具全走这里。拆坏了插件全瘫。

`bridgeState` 现在拼的返回结构**一个字段都不能变**。拆之前先做一件事：把当前 `bridgeState()` 的返回 JSON 存一份基线到 `.tmp/bridge-baseline.json`，拆完再取一次，diff 必须为空。

新增 `test/bridge-server.test.js`（不需要真起 HTTP）：

1. `bridgeAuthorized` 缺 token → false
2. `bridgeAuthorized` token 不对 → false
3. `bridgeState` 输出结构和基线一致（用快照断言）

### 第 5 步：`hermes-poller.js`

搬走：`statusFromSnapshot`、`reviewTransitions`、`applyHermesSnapshot`、`pollHermes`、`startHermesPolling`（`main.js:131-169`、`350-425`）。

顺手修一个现在的问题：`setInterval(pollHermes, 3000)` **没有退避**。Hermes 停着就每 3 秒硬打一次，一直打。

改成：连续失败 3 次后间隔拉到 15 秒，成功一次回到 3 秒。这是唯一允许在这份指令里改的行为，因为它属于「地基」范畴，且改动可测。

新增 `test/hermes-poller.test.js`（用假 bridge）：

1. 快照里 running 为空 → `statusFromSnapshot` 返回 idle 且 `runningCount === 0`，不出现 NaN
2. 任务从 running 变 done → 只产生一次 `done` 边沿事件，不重复播报
3. blocked / error / review 三种状态各自分类正确（不能把 review 当失败）
4. 连续失败 3 次后，下次轮询间隔是 15 秒（用假定时器验）

## 四、顺手清掉测试代码

`main.js` 里散着几处环境变量门控的开发自检，直接写在生产代码里：

```text
PET_APPEARANCE_TEST     main.js:783  截图 + 打印窗口 bounds
PET_STATE_TEST          main.js:935  setInterval 250ms 强推 Live2D 状态
menu-shot.png           main.js:834
settings-shot.png       main.js:815
```

这些在正式启动时判断环境变量为假，不会执行，但**它们占着生产文件的篇幅，也让 main.js 看起来比实际更乱**。

搬法：全部集中到一个 `tools/dev-selfcheck.js`，`main.js` 里只留一行门控调用：

```js
// 开发自检挂在外部文件里，不占主进程篇幅
if (process.env.PET_DEV_SELFCHECK) require('./tools/dev-selfcheck')({ win, petState });
```

搬完必须验：不带 `PET_DEV_SELFCHECK` 启动，行为与现在完全一致（smoke 21/21 就是这条的证据）。

## 五、验收

每一步单独验，别攒到最后一起。

### 每步都要过的

1. `npm test` → `pass N / fail N`，N 只增不减
2. `npm run smoke -- --isolated` → **21/21**，一项不能少
3. `git diff --check` 通过
4. `main.js` 行数：第 1 步后 ≤1200，第 3 步后 ≤900，第 5 步后 ≤500，清完自检 ≤300

### 拆完整体再验一次

5. **零行为变化**：拆之前顺手记下 `getState()` 的完整返回，拆完再取一次，字段名和结构不能变（值可以变，那是时间和任务在动）
6. **桥接服务没坏**：`hermes plugins validate . --json` 通过；如果本机装着插件，`hermes-pet` 的 6 个工具随便调一个能返回
7. 每个新模块都有自己的 `.test.js`，且在 `package.json` 的 `test` 脚本里

### 汇报格式

```text
1. git log --oneline -6（五步五个提交 + 清理）
2. 每步的 main.js 行数曲线：1377 → ? → ? → ? → ? → ?
3. npm test 的 pass 数每一步各一次
4. smoke 21/21 每一步各一次
5. bridgeState 的基线 diff 结果（必须为空）
6. 新增了哪几个测试文件、各测了几条
```

## 六、不许做的事

1. **不改任何 IPC 通道名**。渲染层的 `window.pet.*` 调用一个都不能变，`preload.js` 不用动
2. **不改 `bridgeState` 的返回结构**。Hermes 插件依赖它
3. **不改用户能看到的行为**。除了第 5 步的轮询退避，其他一律零变化
4. **不顺手"优化"逻辑**。拆的过程只搬不改，看到不顺眼的地方记在 `docs/` 里，下一轮单说
5. **不合并步骤**。五个提交就是五个提交，一个提交里干两件事，出问题回滚都回不干净
