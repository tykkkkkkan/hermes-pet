# 指令 07 · 情绪表情有五分之四是空转

> `d281132` 的渲染层改动质量不错，四层结构、优先级、滤镜清理都对。但汇报里那句「待命状态按情绪切换 face-calm/laugh/smug/yawn/frown/speechless/surprised」**只有前三个是真的**，后四个压根没有图源，点上去表情不动。
> 这是本次唯一的功能性缺陷，也正好说明了为什么"自动测试全绿"不等于"功能生效"。

---

## 二、必修（P0）：8 种情绪里 5 种取不到图，表情根本不变

### 断在哪

`renderer/pet.js:250-253` 建了 8 种情绪的映射：

```js
const emotionFace = {
  '平静': 'idle', '开心': 'happy', '得意': 'smug', '犯困': 'sleepy',
  '有点烦': 'frown', '闹别扭': 'speechless', '兴奋': 'surprised', '委屈': 'shy'
};
```

但 `preload.js:15-22` 的 `faceFiles` **一个字都没改**，还是原来那 6 个键：

```js
const faceFiles = legacy.face || {
  idle: v2File('face', 'face-calm'),
  happy: v2File('face', 'face-laugh'),
  sleepy: v2File('face', 'face-yawn'),
  thinking: v2File('face', 'face-serious'),
  angry: v2File('face', 'face-angry'),
  cry: v2File('face', 'face-cry')
};
```

于是 `window.pet.faceSources` 只有这 6 个键，而 `paintFace` 第一行是：

```js
function paintFace(key) {
  const nextKey = String(key || 'idle');
  const src = window.pet.faceSources?.[nextKey];
  if (!src || nextKey === currentFaceKey) return;   // ← src 是 undefined，直接静默返回
```

### 实测对照

按运行时逻辑复现了一遍：

```text
faceSources 现有键: idle, happy, sleepy, thinking, angry, cry

情绪 → face key → 能否取到 src
  平静     → idle         → ✔ 有图
  开心     → happy        → ✔ 有图
  得意     → smug         → ✖ 缺映射，paintFace 静默 return
  犯困     → sleepy       → ✔ 有图
  有点烦   → frown        → ✖ 缺映射，paintFace 静默 return
  闹别扭   → speechless   → ✖ 缺映射，paintFace 静默 return
  兴奋     → surprised    → ✖ 缺映射，paintFace 静默 return
  委屈     → shy          → ✖ 缺映射，paintFace 静默 return
```

**8 种情绪，5 种不生效。** 而且因为是静默 `return`，`petEl.dataset.face` 已经被赋成 `smug` / `frown` 了，DOM 上看着"设进去了"，图片却停在上一次的表情——最隐蔽的那种不生效。

`assets/states/v2/aligned/face/` 里 12 张图都在，`face-smug.png`、`face-frown.png`、`face-speechless.png`、`face-surprised.png`、`face-shy.png`、`face-shock.png` 一个不缺。**不是没素材，是没往 `faceFiles` 里登记。**

### 为什么 smoke 没抓到

新增的那条 `六态状态表情按优先级切换` 测的是 `working` / `thinking` / `success` / `sleep` / `error` / `idle` 这几个**状态**脸，它们的 key（`thinking`/`happy`/`sleepy`/`angry`/`cry`）全在 `faceSources` 里，所以能出图、能断言。

情绪脸一条都没测。`emotionFace` 这张表是这轮新加的、最需要测的东西，反而漏了。

### 改法

**`preload.js`** 把 `faceFiles` 补到 12 个（跟 `aligned/face/` 目录一一对应）：

```js
const faceFiles = legacy.face || {
  idle: v2File('face', 'face-calm'),
  happy: v2File('face', 'face-laugh'),
  sleepy: v2File('face', 'face-yawn'),
  thinking: v2File('face', 'face-serious'),
  angry: v2File('face', 'face-angry'),
  cry: v2File('face', 'face-cry'),
  smug: v2File('face', 'face-smug'),
  frown: v2File('face', 'face-frown'),
  speechless: v2File('face', 'face-speechless'),
  surprised: v2File('face', 'face-surprised'),
  shy: v2File('face', 'face-shy'),
  shock: v2File('face', 'face-shock')
};
```

`shock` 现在没人用，先登记上，留给触摸互动（被戳惊吓）用。登记了不浪费，比将来再加一次映射省事。

## 三、必修（P1）：静默失败要改成可发现

`paintFace` 里 `if (!src) return;` 把"找不到图"和"表情没变"两种情况合并成一个无声的返回。这次就是这么埋进去的。

改成：

```js
function paintFace(key) {
  const nextKey = String(key || 'idle');
  const src = window.pet.faceSources?.[nextKey];
  if (!src) {
    // 映射表里写了但资源表里没登记，属于配置错，不能静默放过
    console.warn(`[pet] 表情 key「${nextKey}」没有对应图源，检查 preload.js 的 faceFiles`);
    return;
  }
  if (nextKey === currentFaceKey) return;
  ...
}
```

以后再有漏登记，控制台一眼看到，不用靠人肉比对两张表。

## 四、必修（P1）：加一条映射完整性测试，把这类问题锁死

这是整份指令里最值钱的一条。**映射表 vs 资源表对齐**这件事，靠人工核对必然漏，做成断言就不会漏。

`test/e2e/pet-smoke.mjs` 加一项，或者 `test/` 下新开一个纯逻辑测试（更快）：

```js
// 表情映射表里出现的每个 key，都必须在 faceSources 里登记过
test('情绪与状态表情映射都能在 faceSources 里找到图源', async () => {
  const { faceSources, emotionFace, stateFace } = /* 从渲染进程或 preload 取 */;
  const keys = Object.keys(faceSources);
  const used = new Set([...Object.values(emotionFace), ...Object.values(stateFace), 'idle', 'cry', 'angry']);
  const missing = [...used].filter((key) => !keys.includes(key));
  assert.deepEqual(missing, [], `以下 face key 在 faceSources 里不存在：${missing.join(', ')}`);
});
```

更彻底的写法：把 `emotionFace` / `stateFace` 两张表从 `renderer/pet.js` 挪到 `pet-actions.js` 旁边做成一个共享模块（比如 `pet-faces.js`），`preload.js` 和 `renderer/pet.js` 都 require 它，这样"表"和"图源"从代码结构上就不可能不一致。代价是多一个文件，收益是这类 bug 永久消失。

**我建议直接做后者**，一次性解决。但如果你想控制这轮改动量，先加测试也够——测试能立刻抓到现在这个 bug。

## 五、要修（P2）：提交拆分没按三件事拆

我给的拆分是三条，实际落成两条，而且混了：

问题在于：`README` 的约定条款、`smoke` 的路径改动、`main.js` 的测试开关，跟"接入表情"是三件不同的事，全塞进了 `feat:`。将来想 revert 表情功能，会把 README 的约定和 smoke 的路径一起回滚。

具体的三个隐性后果：

1. `main.js` 的 `PET_DISABLE_POLL` 是给测试用的开关，藏在 feat 里，下次谁读这条提交会以为它跟表情有关
2. smoke 的截图路径改动在 feat 里，等于"改功能"和"改测试基建"绑死
3. `52fc5ca` 单独 checkout 出来，README 里没有截图例外条款，但仓库里已经有 `docs/pet-action-*.png`，规则和现状脱节

**改法**：已经落库的不动（改历史代价高于收益），**这轮的修复提交按三件事拆**：

```text

```
→ `preload.js`、`renderer/pet.js`（只含 `console.warn` 那处）

```text

```
→ `test/` 下的新用例，或 `pet-faces.js` + 两个引用方

```text

```
→ `docs/指令-06-情绪表情接入.md`、`docs/指令-07-情绪表情修复.md`

**判据不变**：单独 checkout 每条提交，`npm test` 全绿。`fix` 那条单独存在时表情能切换（不缺图源），`test` 那条单独存在时能抓到 bug——如果 `test` 单独 checkout 会红，说明顺序反了，要 `fix` 在前。

## 六、要处理（P2）：人工验收第三轮还是跳过

你写「人工长时间观察待机 30 秒、拖到边缘、四区各连点三次尚未完成」。

这是第三轮了。`4dd5744` 那轮跳、`d281132` 这轮又跳。指令-06 第六节写明了「上两轮都跳了，这轮不能再写在"已知未修"里交差」。

**这三条自动测试确实抓不住，但也不需要"人工长时间观察"这么大的成本**：

- 待机 30 秒 → `npm start` 起桌宠，别看它，干别的，回头想起就瞄一眼。30 秒的等待不该是障碍
- 拖到边缘 → 10 秒的事
- 四区连点三次 → 12 次点击，1 分钟

加起来两分钟。**如果环境起不来 Electron 窗口，就直接说"环境起不来，没法验"**，比写"尚未完成"诚实。不要既不做也不说为什么。

## 七、验收

### 修完这几条

1. **8 种情绪逐个触发，脸都要变**：平静/开心/得意/犯困/有点烦/闹别扭/兴奋/委屈，逐个比对是不是对应到 `face-calm`/`laugh`/`smug`/`yawn`/`frown`/`speechless`/`surprised`/`shy`
2. 故意把 `faceFiles` 里某个 key 注释掉，重新打开桌宠看控制台，要出现 `[pet] 表情 key「xxx」没有对应图源` 的告警（验第三节）
3. `npm test` 里那条映射完整性用例，把 `smug` 从 `faceSources` 删掉后必须变红（验第四节真的有效，不是永远绿）

第 3 条是关键——**能变红的测试才是测试**，永远绿的断言等于没写。

### 之前跳过的三条

4. 待机 30 秒：动作不重复、每次都播完再回待机
5. 拖到屏幕边缘再点：粒子不被窗口边界裁掉
6. 四区各连点三次：第三次扩池、不连续复读

### 汇报格式

```text
1. git status --short、git log --oneline -3
2. npm test → pass N / fail N
3. npm run smoke -- --isolated → pass N / fail N
4. 8 种情绪换脸：逐个给结果，别写"都正常"
5. 故意弄坏映射时的告警截图（或控制台输出原文）
6. 映射完整性测试变红的证据
7. 待机 30 秒 / 拖边缘 / 四区连点三次：逐条过或没过，没验的写原因
```

「都正常」「已覆盖」这类词不要出现在汇报里，逐条给。
