## 二、四处要修

### 问题 1（我写错的）：组头数字和顶部计数对不上

截图里：

| 位置 | 执行中 | 受阻 | 待验收 | 排队 |
|---|---|---|---|---|
| 顶部计数 | **6** | 6 | **6** | **9** |
| 组头 | **5** | 5 | **5** | **5** |

用户看到「待验收 6」和下面的「待验收 5」，第一反应是"到底几个"。

**这是我上一份指令的错**：我让你用 `list.length` 当组头数字，而 `slimGroup` 已经截断到 5 条了，`list.length` 永远是 5。

改法：组头写**真实总数**，截断的差额在列表末尾用一行说明。`main.js` 的 `buildTaskPanel` 每组多带一个 `total`：

```js
function buildTaskPanel(next) {
  const allTasks = Array.isArray(next?.tasks) ? next.tasks : [];
  const queued = allTasks.filter((task) => ['todo', 'ready', 'scheduled'].includes(String(task?.status || '').toLowerCase()));
  const pack = (list) => ({
    items: slimGroup(list),
    total: Array.isArray(list) ? list.length : 0
  });
  return {
    review: pack(next?.review),
    blocked: pack(next?.blocked),
    running: pack(next?.running),
    queued: pack(queued),
    total: allTasks.length
  };
}
```

渲染层：

```js
const html = groups.map(([key, label]) => {
  const group = tasks?.[key] || {};
  const items = Array.isArray(group.items) ? group.items : [];
  const total = Number(group.total) || 0;
  if (!total) return '';
  const rows = items.map((task) => {
    const who = task.assignee ? `<span class="t-who">${escapeHtml(task.assignee)}</span>` : '';
    return `<li><span>${escapeHtml(task.title)}</span>${who}</li>`;
  }).join('');
  const more = total > items.length
    ? `<li class="t-more">还有 ${total - items.length} 条没显示</li>`
    : '';
  return `<div class="t-group"><div class="t-head">${label} <b>${total}</b></div><ul>${rows}${more}</ul></div>`;
}).join('');
```

这样「待验收 6」+ 5 条 + 「还有 1 条没显示」，数字对得上，也知道被截了。

```css
.t-more { color: #a9a3bb !important; font-style: normal; border-bottom: none !important; }
```

### 问题 2：组的顺序该按"要人动手的排前面"

现在顺序是 `执行中 → 受阻 → 待验收 → 排队`，所以一打开面板看到的是「执行中」——**那是最不需要用户操心的**。

真正要用户动手的是「待验收」，其次「受阻」。而它们在第二、第三位，一屏根本看不到。

改成：

```js
const groups = [
  ['review', '待验收'],   // 要人验收，最该先看到
  ['blocked', '受阻'],    // 卡住了，要人介入
  ['running', '执行中'],  // 自己能跑，看看就行
  ['queued', '排队']      // 等着，不用管
];
```

顺序就是优先级。这条改完，用户打开面板第一眼就看到"有 6 条等你验收"。

### 问题 3：面板上下边界各切半个字

截图里滚到中间时，顶部露出「受阻 任务 5」的下半截，底部露出「执行中 任务 5」的上半截。滚动区边界切在半行上，观感很糙。

两个改动一起做：

**a. 每组从 5 条降到 3 条**

四个组 × 5 条 = 20 条，塞进 300px 根本装不下，必然要滚动。降到 3 条后，一屏能看到两组半，重点信息更集中。`main.js:40`：

```js
const PANEL_MAX_PER_GROUP = 3;
```

**b. 上下加渐隐遮罩，切边不硬**

```css
#status-panel {
  /* 滚动区上下做渐隐，避免内容被硬切在半行上 */
  mask-image: linear-gradient(to bottom, transparent 0, #000 10px, #000 calc(100% - 12px), transparent 100%);
  -webkit-mask-image: linear-gradient(to bottom, transparent 0, #000 10px, #000 calc(100% - 12px), transparent 100%);
  padding-bottom: 14px;
}
```

注意 `mask-image` 会作用于整个面板，包括顶部标题——所以 `10px` 那个位置要留够标题的高度，或者把渐隐只做在下缘（`to bottom, #000 calc(100% - 12px), transparent`）。**先只做下缘**，上缘靠 `padding-top` 留白解决，更稳。

```css
#status-panel {
  mask-image: linear-gradient(to bottom, #000 calc(100% - 14px), transparent 100%);
  -webkit-mask-image: linear-gradient(to bottom, #000 calc(100% - 14px), transparent 100%);
  padding-top: 12px;
  padding-bottom: 16px;
}
```

### 问题 4：「总计 27 条」滚到底才看得见

现在它跟着列表一起滚，用户不滚到底就不知道总共多少。

改到顶部计数区，跟四个计数放一起：

```html
<div id="panel-online">离线</div>
<div id="panel-emotion">平静 · 好大爹</div>
<div id="panel-total"></div>        <!-- 新增：共 27 条 -->
<div class="panel-grid"> ... </div>
```

```js
panelTotal.textContent = `看板共 ${Number(s.tasks?.total) || 0} 条`;
```

样式压小一号，别抢主计数：

```css
#panel-total { color: #8d87a3; font-size: 10px; margin-top: 2px; }
```

原来列表底部那行「总计 N 条」删掉，避免同一个数字出现两次。

## 三、别动的

这几处这轮做得对，改上面四条时别顺手改坏：

1. **`lastTasksJson` / `lastAgentsJson` 双缓存**——`JSON.stringify` 比对、没变就不碰 DOM，这是「30 秒 0 次变更」的来源，逻辑保留
2. **`escapeHtml`**——任务标题来自 Hermes，必须转义，不能图省事直接拼
3. **`#status-panel` 的 4px 细滚动条**——`::-webkit-scrollbar` 那三条保留
4. **长标题单行省略**——`.t-head` 之外那条 `overflow:hidden; text-overflow:ellipsis; white-space:nowrap`，截图里已经生效，保留
5. **面板不自动收起**——`paintState` 里别加任何 `classList.add('hidden')`

## 四、验收

修完这四条，按下面逐条给结果，别写"已修复"：

1. **数字一致性**：造 6 条待验收、9 条排队，截图证明组头写「待验收 6」、列表 3 条 + 「还有 3 条没显示」，顶部写「待验收 6」。三个数字要能对上
2. **顺序**：面板一打开，第一组必须是「待验收」。截图
3. **切边**：滚到中间截一张，上下边缘不能出现半个字
4. **总数位置**：不滚动的情况下截图，要能看到「看板共 27 条」
5. **仍然不重建**：MutationObserver 30 秒变更次数仍然是 0（降条数和加 total 字段后要重测一遍，别因为数据结构变了导致每帧都认为"变了"）
6. `npm test` → `pass N / fail N`
7. `npm run smoke -- --isolated` → `pass N / fail N`

第 5 条最容易翻车：`tasks` 结构从 `{running: [...], total}` 改成 `{running: {items, total}, total}`，如果 `buildTaskPanel` 每次返回新对象、字段顺序不稳定，`JSON.stringify` 比对就会永远不相等，列表每帧重建——那样又回到会闪的老路了。改完必须重测这一项。
