## 二、必修（P0）：打包版连不上模型

第 5 条你写「模型回复因打包进程访问 DeepSeek 返回 fetch failed，未通过完整回复验收」。

**这不是"验收跳过"，是功能缺陷。** 打包版聊天发不出去，等于这个包只完成了一半。而且你把它放在"实测"清单第 5 条里轻轻带过，读的人容易滑过去。

### 先定位，别猜

`main.js:234-262` 的 `askModel` 用的是 Node 全局 `fetch`（undici），不是 Electron 的 `net.fetch`，也没读系统代理。`fetch failed` 是 undici 抛的通用错误，**真正的原因在 `error.cause` 里**。

现在代码里没有把 cause 打出来，所以只知道"失败了"。先加日志：

```js
try {
  const response = await fetch(`${base}/chat/completions`, { ... });
  ...
} catch (error) {
  // undici 的 fetch failed 只说明网络层炸了，真正原因在 cause 里：
  // ECONNREFUSED / ENOTFOUND / CERT_HAS_EXPIRED / UND_ERR_CONNECT_TIMEOUT 各不相同
  console.error('[pet] 模型请求失败:', error.message, '| cause:', error.cause?.code || error.cause?.message || error.cause);
  throw error;
}
```

然后**在打包版里跑一次**，把 `cause` 的原文贴出来。按常见的三种分别处理：

| cause | 含义 | 处理方向 |
|---|---|---|
| `ECONNREFUSED` / `ENOTFOUND` | 连不上、域名解析不出 | 系统代理没被 Node 读到。加 `undici` 的 `ProxyAgent`，或者改用 Electron 的 `net.fetch`（它走 Chromium 网络栈，继承系统代理） |
| `UND_ERR_CONNECT_TIMEOUT` | 连接超时 | 同上，或者检查 Windows 防火墙对新 exe 的拦截 |
| `CERT_*` / `SELF_SIGNED_CERT_IN_CHAIN` | 证书链问题 | 代理软件的 MITM 证书没被 Node 信任，改用 `net.fetch` 最省事 |

**我倾向于直接用 `net.fetch`**：桌宠是 Electron 应用，主进程已经 import 了 `net`（`main.js:1`），`net.fetch` 继承 Chromium 的网络栈，系统代理、证书、DNS 全都跟着走，和源码版的行为也一致。改起来就是一行：

```js
const { net } = require('electron');
const response = await net.fetch(`${base}/chat/completions`, { ... });
```

但**先看清 cause 再动手**，不要直接换。万一是防火墙拦的，换 `net.fetch` 也没用，得让用户在防火墙弹窗里点允许。

### 另一个可能，顺手排掉

`getApiKey()` 依赖 `safeStorage`。如果打包版读 `settings.json` 读不到 key，`askModel` 会走 `localReply(text)` 而不是发请求——但那样不会有 `fetch failed`。所以 key 应该读到了。**这一点在日志里顺手确认一下**：打出 `apiKey 长度` 和 `settings.apiBase`，确认请求确实发出去了。

## 三、该做（P1）：砍掉 32.7MB 的 pixi 全家桶

`app.asar` 里 `node_modules` 36.7MB，其中：

```text
@pixi                     21.4 MB
pixi.js                   11.3 MB
lodash                     1.3 MB
pixi-live2d-display        1.3 MB
async / qs / earcut / fs-extra   0.8 MB
```

而 `renderer/index.html:53` 只用了一个文件：

```html
<script src="../node_modules/pixi.js/dist/browser/pixi.min.js"></script>
```

`pixi.min.js` 大约 1.7MB。**剩下 32MB 全是 `lib/`、`dist/*.map`、TypeScript 声明、esm/cjs 各一份的重复产物。**

### 改法：vendor 一个文件，node_modules 整个不进包

1. 把 `node_modules/pixi.js/dist/browser/pixi.min.js` 拷到 `renderer/vendor/pixi.min.js`（1.7MB，进仓库）
2. `renderer/index.html:53` 改成 `<script src="vendor/pixi.min.js"></script>`
3. `renderer/live2d-test.html` 这条**不动**——它是开发验证页，只在 `PET_LIVE2D_TEST=1` 时打开，打包时整个排除掉就行
4. `package.json` 的 `build.files` 加 `"!node_modules/**"`
5. `pixi.js` / `pixi-live2d-display` 从 `dependencies` 挪到 `devDependencies`（源码里没有任何 `require('pixi')`，只有 html 的 script 标签）

改完 `asar` 应该从 53.9MB 降到 **18~20MB**，安装包从 135MB 降到 **105MB 上下**。

**这是这轮风险最高的改动**，因为它动的是 `index.html` 的脚本加载路径，改错了桌宠直接白屏。所以第 4 节第 1 条必须验，而且要在打包版里验，不是源码版。

### 顺带：Electron 自带的 74MB 也能砍

```text
dist/win-unpacked/locales            49 MB   ← 语言包，只用 zh-CN 的话能留 1MB
dist/win-unpacked/dxcompiler.dll     25 MB   ← D3D 着色器编译器，纯 2D 桌面小工具用不到
dist/win-unpacked/vk_swiftshader.dll  5.3 MB ← 软件渲染兜底
```

`locales` 可以在 `build` 里加 `"electronLanguages": ["zh-CN", "en-US"]` 裁。`dxcompiler.dll` 和 `vk_swiftshader.dll` 可以用 `afterPack` 钩子删，但**这两个删了有风险**：某些显卡驱动下 Chromium 会fallback 到 SwiftShader，删了就是黑屏。**建议只裁 locales，那两个不动**，留着 30MB 换稳定性，值。

## 四、该做（P2）：版本号、桥接文件、产物重打

### 1. 版本号升到 0.2.0

`package.json` / `plugin.yaml` 都还是 `0.1.0`。这一轮加了三样东西：仪表盘、情绪表情、五个模块拆分，按语义化版本该是 `0.2.0`。

三处要一起改：`package.json` 的 `version`、`plugin.yaml` 的 `version`、`CHANGELOG.md` 加一节。

单独一条提交，别混在打包配置里。

### 2. 桥接文件会被互相删掉

`bridge-server.js:132-137`：

```js
function stop() {
  try { server?.close(); } catch {}
  server = null;
  token = '';
  try { fs.unlinkSync(bridgeFile()); } catch {}   // ← 无条件删
}
```

两个实例并存时（比如隔离 userData 的测试实例 + 正式实例），先退出的那个会把另一个的桥接文件删掉。剩下的那个进程还在跑，但 `hermes-pet-bridge.json` 没了，Hermes 插件连不上它——两个桌宠都显示「Hermes 离线」就是这个。

改法：删之前先确认文件里的 `pid` 是自己。

```js
function stop() {
  try { server?.close(); } catch {}
  server = null;
  token = '';
  try {
    // 只删自己写的桥接文件。两个实例并存时，后起的会覆盖文件里的 pid，
    // 退出的那个要是无条件删，就把还活着的那个的文件删掉了。
    const current = JSON.parse(fs.readFileSync(bridgeFile(), 'utf8'));
    if (Number(current?.pid) === process.pid) fs.unlinkSync(bridgeFile());
  } catch {}
}
```

### 3. 改完必须重新打包

第二节的日志、第三节的 vendor 改动、第四节的版本号，全部落完之后跑一次：

```bash

```

## 五、验收

全部在**新打出来的 0.2.0 包**上验。

### 打包版必须过的

1. **不白屏**：装好启动，角色立绘正常显示（验证 `vendor/pixi.min.js` 路径改对了）
2. **模型能回话**：聊天窗发一条「今天还剩什么活」，要收到真实回复，不能是 `localReply` 的兜底话术
3. **联网失败日志**：故意把 `apiBase` 改成一个不通的地址，控制台要打出 `cause:` 后面跟具体错误码，不是光一个 `fetch failed`
4. **桥接文件不再被误删**：同时起源码版和打包版（打包版会被单例锁挡掉，用 `--user-data-dir` 隔离起第二个），然后关掉其中一个，剩下的那个 `hermes-pet-bridge.json` 必须还在、`pid` 指向还活着的那个
5. 体积：`ls -la dist/*.exe` 的数字，安装包目标 ≤110MB，`app.asar` 目标 ≤20MB
6. 前面指令-12 那 12 条里，2/3/4/6/7/9/10/11 再抽查一遍（这轮动了 index.html 和 asar 内容，不能假设之前的结果还成立）

### 汇报格式

```text
1. git log --oneline -4
2. dist/*.exe 的大小和时间戳（必须是这轮新打的）
3. app.asar 大小，以及解析出的 node_modules / assets 各占多少
4. 第 2 条的聊天回复原文
5. 第 3 条的 cause 日志原文
6. 第 4 条：关掉一个之后，剩下那个的 bridge.json 内容
7. npm test / smoke / plugin validate 的结果
```

第 4 条和第 5 条是这轮的关键证据。**"fetch failed" 这四个字以后不要再出现在汇报里**，要么贴 cause，要么说没测。
