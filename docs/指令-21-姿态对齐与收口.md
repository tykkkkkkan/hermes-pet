# 指令 21 · 姿态对齐与收口

> 姿态素材接进来了，但**尺寸和位置全错**，切换瞬间角色会缩小并往左跳 76px。这份先修这个，再收拾剩下的零碎。
> 分四批，前两批是必修，后两批可以缓。

---

## 一、P0：姿态层对不齐

### 实测数据

连戳 4 次触发 `sulky`，`pose-back.png` 正常加载（`opacity: 1`），但：

```text
pose 层    379x379   top 138   left -20     ← 左边超出窗口 20px
puppet    227x378   top 121   left 56
窗口       340x501
```

`left: -20` 意味着姿态层的左边缘在窗口外面，而 puppet 的 canvas 在 56。**差 76px，还小一圈。**

### 根因有三层

**第一层：`.pose-layer` 写死了 374px。**

```css
.pose-layer {
  width: 374px; height: 374px;
  left: 50%; margin-left: -187px;
  bottom: -17px;
}
```

窗口只有 340 宽，374 必然溢出。而且 `petScale` 从 70% 到 140% 可调，窗口尺寸会变，写死就永远对不齐。

**第二层：两套坐标系不一样。**

- `pet-layers/*.png` 是 **448×841**（`meta.json` 的 `canvas`）
- `aligned/state/pose-*.png` 是 **1024×1024**

puppet 按 `448×841` 缩放定位：

```js
const cw = meta.canvas.width, ch = meta.canvas.height;   // 448, 841
const s = Math.min((w * 0.99) / cw, (h * 0.98) / ch);    // 缩放比
root.scale.set(s);
root.position.set(w/2 - (cw*s)/2, h - ch*s - shadowPad);
```

而姿态层直接把 1024 的整张图塞进 374px 的正方形，两者不是同一个比例。

**第三层：1024 图里角色不占满画布。**

实测每张 pose 图的不透明包围盒：

```text
state-idle     1024²   x[294,729] y[144,972]   436 × 829
pose-back      1024²   x[293,730] y[145,972]   438 × 828
pose-side      1024²   x[355,668] y[146,972]   314 × 827
pose-wave      1024²   x[272,751] y[101,972]   480 × 872
state-annoyed  1024²   x[287,736] y[145,972]   450 × 828
```

**所有姿态图的脚底都固定在 y=972** —— 这是天然的锚点。头顶在 101~146 之间浮动（挥手时手举起来，所以高到 101）。

而 `pet-layers` 那边：

```text
body.png  448×841  x[7,438]  y[232,834]
head.png  448×841  x[2,445]  y[2,293]
```

head 顶到 y=2，body 底到 y=834。合成后角色区域约 `x[2,445] y[2,834]`，也就是 **443×832**。

**436×829 和 443×832 几乎同尺寸** —— 说明这两个画布是同一角色、同一时刻的不同分辨率输出，只是裁剪窗口不同。

## 二、修法：先标定，再对齐

### 第 1 步：写一个标定工具 `tools/align-pose.js`

目标：求出 `1024×1024` 的图裁成 `448×841` 时，左上角在 1024 图里的坐标 `(ox, oy)`。

算法不复杂，用包围盒就能算：

```js
// 1024 图里角色区域 436×829，448 画布里角色区域 443×832
// 两者比例 k = 443/436 ≈ 1.016，说明 1024 图其实比 448 画布略小一点点
// 用脚底对齐 + 水平居中求解：
const k = 443 / 436;                       // 448 画布相对 1024 的放大比
const ox = (2 + 445) / 2 - ((294 + 729) / 2) * k;   // 让水平中心对齐
const oy = 834 - 972 * k;                  // 让脚底对齐
```

跑出来把结果写进 `assets/pet-layers/pose-meta.json`：

```json
{
  "source": "1024x1024 状态图 → 448x841 画布",
  "scale": 1.016,
  "offsetX": -72.6,
  "offsetY": -153.6,
  "footY": 972,
  "note": "所有 pose 图脚底固定在 972，以 state-idle 为基准标定"
}
```

**这个数要验**：拿 `state-idle.png` 按 `(ox, oy, k)` 变换到 448×841，和 `body.png + head.png` 合成图做逐像素比对，**平均误差要小于 3**（RGB 三通道差值的平均）。误差超了说明标定错了，别往下走。

### 第 2 步：把 7 张 pose 图统一预处理成 448×841

新增 `tools/normalize-poses.js`，按 `pose-meta.json` 把每张 pose 图统一变换到 448×841 画布，输出到 `assets/pet-layers/pose/`：

```text
assets/pet-layers/pose/
├─ pose-back.png      448×841
├─ pose-side.png      448×841
├─ pose-wave.png      448×841
├─ pose-point.png     448×841
├─ pose-annoyed.png   448×841
├─ pose-trust.png     448×841
└─ pose-walk.png      448×841
```

变换规则：先按 `k` 缩放，再平移到 `(ox, oy)`，超出 448×841 的部分裁掉，边缘用 1px alpha 羽化避免硬切。

**这样 pose 图和 `body/head/eyes/mouth/shadow` 就在同一个坐标系里了**，后面一切对齐问题自动消失。

### 第 3 步：`.pose-layer` 改成和 canvas 同盒子

```css
.pose-layer {
  position: absolute;
  inset: 0;                    /* 和 #pet-live2d-host 完全一致 */
  width: 100%;
  height: 100%;
  object-fit: contain;         /* 448×841 的图，等比放进同比例的容器，不会变形 */
  object-position: center bottom;
  pointer-events: none;
  -webkit-user-drag: none;
  opacity: 0;
  transition: opacity .2s ease;
  z-index: 2;
}
```

`#pet-live2d-host` 是 `inset: 0`，所以 `#pet-gesture` 有多大它就有多大。pose 层用同一套，**不管 `petScale` 怎么调都自动跟随**，不用再算任何数字。

**但还有一个细节**：puppet 的 `root.position` 在底部留了 `shadowPad`（9~20px），角色不是贴底的。pose 图是贴底的（脚底 y=834 在 841 画布里，留了 7px）。

所以 `object-position: center bottom` 会让 pose 角色比 puppet 角色低 10px 左右。**改用 `padding-bottom` 补偿**：

```css
.pose-layer {
  padding-bottom: 10px;   /* 补 puppet 的 shadowPad，具体值从 getViewport() 读 */
  box-sizing: border-box;
}
```

或者更准：让 `pet-puppet.js` 暴露 `getViewport()`，`renderer/pet.js` 拿 `shadowPad` 动态设。

## 三、第二批：把验收补齐

### 3.1 上一轮的放大图拍错了位置

`neck-cut-zoom-4x.png` 放大的是**头部**，切缝在更下面的脖子处，那张图根本没拍到切缝。

`meta.json` 里 `head.cutY = 258`，448×841 的画布里切缝在 y=258，也就是从上往下 30.7% 的位置。放大截图的裁剪区域应该是：

```js
// 448×841 画布 → 屏幕坐标
const vp = window.petLive2d.getViewport();
const cutScreenY = vp.rootY + 258 * vp.scale;
// 裁剪 y 从 cutScreenY - 30 到 cutScreenY + 30，x 覆盖角色宽度
```

重拍一张，范围 `y ∈ [cutY-30, cutY+30]`，放大 4 倍。

### 3.2 「y=258 重叠宽度 432px」这个数是错的

我实测是 **187px**。187 恰好是 `body.png` 在 y=258 那一行原本的不透明像素数，说明补绘没增加这一行的覆盖，只是多了上面 26 行。

432 大概是算了 head 和 body 的**并集**。以后报这类数字要说清是交集还是并集。

### 3.3 暴露 puppet 的实时骨骼值

上一轮我判断「头身错峰」失败，因为头部区域被眼睛的持续变化淹没了，像素测量分辨不出来。

在 `pet-puppet.js` 里把当前姿态暴露出来：

```js
// 和 __petPuppetDebug 一起暴露
getPose() {
  return {
    rot: cur.rot, dy: cur.dy, eye: cur.eye, mouth: cur.mouth,
    breath: cur.breath, lean: cur.lean,
    jump: imp.jump, scale: root?.scale?.x || 1
  };
}
```

有了这个，验收就能写成自动断言：动作期间每 70ms 采一次 `getPose()`，**`rot` 的峰值时刻和 `lean` 的峰值时刻必须相差 ≥ 70ms**，这才叫错峰。

## 四、第三批：清理收尾

### 4.1 puppet 模式下 CSS 手势在空跑

`#pet-inner` 已经是 `display: none`，但 `playAction` 还在给 `#pet-gesture` 加 `gesture-active`、设 `animationDuration`、挂 `animationend` 监听。动画在跑但看不见。

```js
// 现在
gestureEl.classList.add('gesture-active');
const puppetActive = window.petLive2d?.isReady?.() && action.tracks;
if (puppetActive) { window.petLive2d.playTrack(...); }

// 改成：puppet 在跑就不碰 CSS
const puppetActive = window.petLive2d?.isReady?.() && action.tracks;
if (puppetActive) {
  window.petLive2d.playTrack(action.tracks, action.duration, scale);
} else {
  gestureEl.style.animationDuration = `${action.duration}ms`;
  void gestureEl.offsetWidth;
  gestureEl.classList.add('gesture-active');
  // animationend 和兜底计时器也只在 else 分支里挂
}
```

`smoke` 里那些断言 `gesture-active` 的用例要跟着改——puppet 模式下改成断言 `getPose()` 的值在变。

### 4.2 `formatUtterance` 直接改状态对象

`main.js` 的 `formatUtterance` 里：

```js
petState.address = address;
petState.addressHistory = [...history, address].slice(-2);
```

绕过 `petStateStore.set()` 直接写字段，状态模块管不着自己的状态。改成：

```js
petStateStore.set({ address, addressHistory: [...history, address].slice(-2) });
```

### 4.3 README 路线图

```diff
- - [ ] 语音输入转写走本地 ASR（当前仅浏览器 SpeechRecognition 入口）
+ - [x] 语音输入转写走本地 ASR（sherpa-onnx WASM + 首次启动下载模型，实测平均 94.3%）
```

### 4.4 补 `hermes-bridge.js` 的单测

它是仪表盘、状态播报、Agent 面板三处的数据源头，`normalizeBoard` 是纯函数，现有 2 个用例太少。补这些边界：

```text
1. board 为 null / {} / { columns: [] }        → counts 全 0，不抛
2. 任务缺 title 和 name                         → 用「任务 #id」兜底
3. title 是空字符串                             → 同上
4. 同一个 id 出现在两列                         → 不重复计数
5. assignee 有但不在 running 里                  → status 是 idle
6. board.assignees 是 undefined                 → agents 是空数组，不是 undefined
7. 任务 status 大小写混用（RUNNING / Running）    → 都归一到 running
```

## 六、验收

### 第一批（对齐）

```text
1. 三个数字：标定算出的 k / ox / oy，以及 state-idle 变换后的逐像素平均误差（要 < 3）
2. pose 层和 canvas 的实测盒子：rect 宽高、top、left 四个值必须一致（允许 ±2px）
3. petScale 设 80% 和 140% 各截图一次，两种情况都要对齐
4. 连戳 4 次进 sulky，截图看角色大小和位置有没有跳变
```

第 2 条是硬判据。`getBoundingClientRect()` 读 `.pose-layer` 和 `#pet-live2d-host canvas`，两组的 `width/height/top/left` 必须一致。

```text
5. 重新拍的切缝放大图（y ∈ [cutY-30, cutY+30]）

```

## 七、不许做的

1. **不要用 `transform: scale()` 去凑 pose 层的尺寸**。要改的是盒模型本身，用缩放凑会在 `petScale` 变化时再次失准
2. **不要跳过标定直接手填 `ox/oy`**。1024 和 448 两套坐标的映射必须用逐像素比对验证过，猜的数值差几像素就会露缝
3. **不要在没有 `pose-meta.json` 验证的情况下批量生成 normalized pose**。标定错了，7 张图全部要重做
4. **不要顺手改 `meta.json` 的 `canvas` 和 `head.cutY`**。这两个值是骨骼系统的基础，动了整套都要重新对齐
