# 指令 16 · 拖拽变大、声音生硬、分层断层

> 用户报了三个体验问题，第一个是硬 bug，我实测定位到了根因。第二个是选型问题，第三个要看素材。
> 前两条能给具体修法，第三条要先看清素材再动手。

## 一、P0：拖着拖着窗口会变大（已定位）

### 实测证据

用主进程 inspector 直接读 `BrowserWindow.getBounds()`，拖 5 次（每次 dispatch 6 个 `mousemove`）：

```text
初始          {x:1280, y:485, w:341, h:501}
第 1 次后     {x:1280, y:485, w:347, h:507}
第 2 次后     {x:1280, y:485, w:353, h:513}
第 3 次后     {x:1280, y:485, w:359, h:519}
第 4 次后     {x:1280, y:485, w:365, h:525}
第 5 次后     {x:1280, y:485, w:371, h:531}
```

位置 `x/y` 完全没变，**宽高每次 +6**。

把每次拖拽的 `mousemove` 从 6 个改成 3 个，再测：

```text
初始          w:341 h:501
第 1 次后     w:344 h:504      ← +3
第 2 次后     w:347 h:507      ← +3
第 3 次后     w:350 h:510      ← +3
```

**每调用一次 `drag-move`，窗口宽高各 +1 逻辑像素。** 6 个 mousemove 就 +6，3 个就 +3。

### 根因

`main.js:617-622`：

```js
ipcMain.on('drag-move', () => {
  if (!win || !dragGrab) return;
  const c = screen.getCursorScreenPoint();
  const [nx, ny] = clampToWorkArea(c.x - dragGrab.x, c.y - dragGrab.y);
  win.setPosition(nx, ny);      // ← 这里
});
```

这台机器 `devicePixelRatio = 1.75`（175% 缩放）。`setPosition` 在 Windows 上走 `SetWindowPos`，对 `transparent: true` + `frame: false` + `resizable: false` 的窗口，DIP↔物理像素换算的取整误差**每次都往大的方向偏 1px**，累积起来就是「拖着拖着越来越大」。

这也解释了为什么用户能立刻感觉到——他平时设的是 `petScale: 80`，窗口本来就小，+1px/次的膨胀比例更明显。

### 修法：拖拽时显式带尺寸

`drag-begin` 记下当前尺寸，`drag-move` 用 `setBounds` 带着尺寸一起设，把取整误差钉死：

```js
let dragGrab = null;
let dragSize = null;   // 新增

ipcMain.on('drag-begin', () => {
  if (!win) return;
  const [x, y] = win.getPosition();
  const b = win.getBounds();
  const c = screen.getCursorScreenPoint();
  dragGrab = { x: c.x - x, y: c.y - y };
  // setPosition 在 175% DPI + 无边框透明窗口下，每调一次会把宽高各撑大 1px，
  // 拖几下桌宠就变大。这里记下拖拽开始时的尺寸，每次 setBounds 显式带上。
  dragSize = { width: b.width, height: b.height };
});

ipcMain.on('drag-move', () => {
  if (!win || !dragGrab) return;
  const c = screen.getCursorScreenPoint();
  const [nx, ny] = clampToWorkArea(c.x - dragGrab.x, c.y - dragGrab.y);
  win.setBounds({ x: nx, y: ny, ...(dragSize || {}) });
});

ipcMain.on('drag-end', () => {
  dragGrab = null;
  dragSize = null;
});
```

**注意 `clampToWorkArea` 里用的是 `win.getBounds()` 的宽度**（`main.js:600`）。如果窗口已经被撑大了，clamp 的边界会偏。修完之后这个值就稳定了，不用额外改。

### 验收

`drag-move` 改成 `setBounds` 之后，用同样方法测：

```text
拖 10 次，每次 6 个 mousemove，getBounds() 的 w/h 必须一直是 341/501
```

**要贴真实数字，不能说「已修复」。** 这台机器 DPR=1.75，正是能复现的环境，别在别的缩放下测。

## 二、P1：声音生硬，要可爱的

### 现状

`renderer/chat.js:485-496`：

```js
function readAloud(text) {
  ...
  const utterance = new SpeechSynthesisUtterance(text);
  utterance.lang = 'zh-CN';
  const voice = window.speechSynthesis.getVoices().find((item) => item.lang.toLowerCase().startsWith('zh'));
  if (voice) utterance.voice = voice;
  window.speechSynthesis.speak(utterance);
}
```

`find(lang.startsWith('zh'))` 就是**列表里第一个中文音色**。Windows 上通常是 `Microsoft Huihui Desktop`——那是十几年前的 SAPI 4/5 音色，机械感极强，语速和停顿都像导航播报。

### 先做一件事：把可用音色全列出来

在 `readAloud` 之前加一段调试，或者直接在 DevTools 里跑：

```js
speechSynthesis.getVoices().filter(v => /zh|Chinese/i.test(v.lang + v.name))
  .map(v => `${v.name} | ${v.lang} | ${v.localService ? '本地' : '在线'}`)
```

**把这份清单原样贴给用户看。** Windows 11 + 装了中文语音包的话，通常能看到 `Microsoft Xiaoxiao`、`Microsoft Xiaoyi`、`Microsoft Yunxi` 这类 OneCore 音色——**比 Huihui 好听一个档次，而且不用装任何东西**。

### 按清单分三种情况处理

| 清单里有什么 | 做法 |
|---|---|
| 有 `Xiaoyi` / `Xiaoxiao` / `Yunxia` 这类 | 优先选它们，按「可爱度」排：`Xiaoyi > Xiaoxiao > Yunxia > Yaoyao > Huihui`。`Xiaoyi`（晓伊）是幼态童声，最贴「可爱」；`Xiaoxiao`（晓晓）是活泼女声 |
| 只有 `Huihui` / `Kangkang` 这类老音色 | 说明没装 OneCore 语音包。先提示用户在「设置 → 时间和语言 → 语音 → 添加语音」里装中文（简体）语音包，装完重启桌宠就能选到 |
| 一个中文音色都没有 | 系统连中文语音都没装，同上，先装语音包 |

### 如果 OneCore 音色也不够可爱，才考虑 edge-tts

`zh-CN-XiaoyiNeural` 是微软 Azure 的神经网络音色，比本地的 OneCore 版更自然（本地版是压缩过的）。用户本机的 Hermes 已经在用 `tts.edge.voice = zh-CN-XiaoyiNeural`。

**但这轮先别接。** 理由：

1. 本地语音包能解决就先解决，零依赖
2. edge-tts 要联网，桌宠断网就哑了
3. 接它需要新增依赖 + 音频缓存 + 播放通道，是独立一轮的事

**顺序：先列出音色清单 → 换成最好的本地音色 → 用户听完还不满意，下一轮再上 edge-tts。**

### 顺手改音色参数

不管用哪个音色，这几个参数能显著改善「生硬感」：

```js
utterance.rate = 1.08;    // 默认 1.0 偏慢，稍快一点更活泼
utterance.pitch = 1.15;   // 音调抬高一点，明显更可爱
utterance.volume = 1.0;
```

`pitch` 从 1.0 提到 1.15 是「可爱」最直接的手段，比换音色见效还快。**这两个值要读设置里的 `voiceRate`（现在是 100），把它按比例映射过去**，别写死。

## 三、P1：人物分层有断层

### 现象

用户截图上能看到：帽子/头发/脸之间有深色轮廓线，身体和披风之间也有分界感，整体像「贴纸叠起来的」而不是一体的。

### 先查清素材

现在的渲染是三层：

```html
<img id="pet-body"  src=".../state-idle.png" />          <!-- 整图，已经含脸 -->
<img id="pet-face"  src=".../face/face-calm.png" />      <!-- 表情贴片 -->
<img id="pet-blink" src=".../state-idle-blink.png" />    <!-- 眨眼整图 -->
```

**关键问题：`state-idle.png` 是整图（脸已经在里面了），再叠一层 `face-calm.png` 贴片，贴片的边缘就会和底下的脸形成重影/硬边。** 用户看到的那圈深色轮廓，很可能就是贴片的 alpha 边缘。

查这几件事，把结果贴出来：

1. `face-calm.png` 的实际内容——用图看，是「只有眼睛和嘴的差分」，还是「整张脸（含轮廓）」？
2. 它的 alpha 通道边缘是不是硬的（0/255 跳变），还是羽化的（有中间值）？
3. `state-idle.png` 和 `state-idle-blink.png` 之间，除了眼睛之外有没有其它像素差异？
4. `assets/states/v2/aligned/` 下面 `state/`、`state2/`、`face/` 三组的图，是不是同一张底图衍生的？

用 node 读 png 的 alpha 分布能判断第 2 条：

```js
// 统计 alpha 直方图：如果只有 0 和 255，边缘就是硬的
const { PNG } = require('pngjs');
const png = PNG.sync.read(require('fs').readFileSync('assets/states/v2/aligned/face/face-calm.png'));
const hist = {};
for (let i = 3; i < png.data.length; i += 4) {
  const a = png.data[i];
  const bucket = a === 0 ? '0' : a === 255 ? '255' : '1-254';
  hist[bucket] = (hist[bucket] || 0) + 1;
}
console.log(hist);
```

### 按结果选修法

| 查到的情况 | 修法 |
|---|---|
| `face-*.png` 是「整张脸含轮廓」的贴片 | 表情贴片不该盖在已有的脸上。改成**只导出眼睛和嘴的差分区域**，或者让 body 图用「无脸版」，一层脸图层负责五官 |
| alpha 边缘是硬的（只有 0/255） | 给贴片做 1~2px 的 alpha 羽化，用 `pngjs` 遍历边缘像素做模糊 |
| body 和 blink 之间有多余差异 | 拆层的基准图不一致，要重新从同一张原图生成 |
| 三组图尺寸/对齐基准不同 | 同理，重新对齐 |

**这轮先交付诊断结论，别直接改素材。** 素材改动不可逆（要保留原图），先看清再动手。

如果诊断出来是「贴片边缘硬」，修法是纯程序化的（羽化 alpha），可以让 Codex 直接做，但**必须保留原图备份**。

## 四、验收

### 拖拽（这条最重要）

```text
1. 拖 10 次，每次贴 getBounds() 的 w/h，必须恒定
2. 拖到屏幕四边、再拖回来，w/h 仍然恒定
3. 拖到第二块显示器（如果有）再拖回来，w/h 仍然恒定
```

第 3 条是重点——跨屏时 DPR 会变（1.75 → 1.0 或 2.0），`setBounds` 带尺寸的修法在那里要重新验一次。

### 声音

```text
1. speechSynthesis.getVoices() 里所有中文音色的完整清单
2. 最终选了哪个，为什么
3. rate 和 pitch 的最终值
```

### 分层

```text
1. 三个诊断问题的答案
2. alpha 直方图的实际数字
3. 贴一张放大 3 倍的脸部截图，能看清楚接缝
```

## 五、不许做的

1. **这轮不接 edge-tts**。先把本地音色用到位
2. **不改素材之前先备份**。`assets/states/v2/aligned/` 里的图是花过功夫对齐的，覆盖了就没了
3. **不用 `setPosition` 修拖拽**。必须换成带尺寸的 `setBounds`，否则换个 DPI 又复发
4. **不在 100% 缩放下验拖拽**。这台机器是 175%，就在 175% 下验，那才是能复现的环境
