## 二、打包前必须知道的三件事

### 1. `assets` 有 160MB，但真正要进包的是 14MB

```text
assets/states/v2/shot      50M   ← 开发截图，不进包
assets/states/v2/face      36M   ← 未对齐原图，不进包
assets/states/v2/state     35M   ← 未对齐原图，不进包
assets/states/v2/state2    19M   ← 未对齐原图，不进包
assets/states/v2/aligned   14M   ← 运行时实际用的，进包
assets/live2d             4.8M   ← .gitignore 里就排除了，不进包
assets/hermes-chibi.png   1.7M   ← 托盘图标在用（main.js:369），进包
assets/pet-layers         969K   ← 先核引用再决定
assets/fx / assets/ui     722K   ← 进包
```

不排的话安装包会大出一个量级。但**排除哪些必须逐个核引用**，不能凭目录名猜：`grep -rn "assets/pet-layers" --include=*.js .` 之类先确认。`assets/hermes-chibi.png` 看着像废弃素材，实际是托盘图标，排掉了托盘就没图标。

### 2. `renderer/index.html:53` 直接引 `../node_modules/pixi.js/dist/browser/pixi.min.js`

```html
<script src="../node_modules/pixi.js/dist/browser/pixi.min.js"></script>
```

打包后 `index.html` 在 `app.asar/renderer/` 里，这个相对路径要能指到 `app.asar/node_modules/pixi.js/dist/browser/pixi.min.js`。`pixi.js` 是 `dependencies` 里的生产依赖，electron-builder 默认会打进去，**但 `asar` 打开后这个 `<script src>` 能不能加载要实测**——这是打包后最容易白屏的地方。

### 3. 写在磁盘上的东西只有一处，这个是好消息

```text
main.js:684   fs.mkdirSync(HERMES_DIR, { recursive: true })     ← LOCALAPPDATA/hermes
```

全项目只有这一处 `mkdirSync`，写文件全在 `LOCALAPPDATA/hermes/` 下（settings、state、chat.json、position.json、桥接文件）。`__dirname` 只用来读（persona.json、renderer、preload、assets、petasset 协议基准）。

**这意味着没有「asar 只读导致写入失败」的坑**——但前提是别在打包时往 `__dirname` 下写任何东西。`tools/dev-selfcheck.js` 会写 `.tmp/*.png`，那个文件已经被门控了、也不会被打进包（见下面 `files` 排除）。

## 三、打包配置

### 1. 装依赖

```bash
npm i -D electron-builder
```

### 2. `package.json` 补 `build` 段

```json
{
  "scripts": {
    "dist": "electron-builder --win",
    "dist:portable": "electron-builder --win portable"
  },
  "build": {
    "appId": "com.tykkkkkkan.hermes-pet",
    "productName": "赫尔墨兹",
    "directories": { "output": "dist", "buildResources": "assets/ui" },
    "files": [
      "**/*",
      "!test/**",
      "!docs/**",
      "!tools/**",
      "!.tmp/**",
      "!.git/**",
      "!dist/**",
      "!*.md",
      "!CHANGELOG.md",
      "!assets/states/v2/shot/**",
      "!assets/states/v2/face/**",
      "!assets/states/v2/state/**",
      "!assets/states/v2/state2/**",
      "!assets/live2d/**"
    ],
    "asar": true,
    "win": {
      "target": [{ "target": "nsis", "arch": ["x64"] }],
      "icon": "assets/ui/hermes-pet.ico"
    },
    "nsis": {
      "oneClick": false,
      "allowToChangeInstallationDirectory": true,
      "createDesktopShortcut": true,
      "createStartMenuShortcut": true,
      "shortcutName": "赫尔墨兹",
      "artifactName": "hermes-pet-${version}-setup.${ext}"
    },
    "portable": {
      "artifactName": "hermes-pet-${version}-portable.${ext}"
    }
  }
}
```

`productName` 用中文名的话，安装目录和进程名会带中文，**如果你更希望 exe 文件名是英文，`productName` 就写 `hermes-pet`，只在 `nsis.shortcutName` 里用中文**。选后者更省事，先按后者做。

**不做代码签名**（自用，`CSC_IDENTITY_AUTO_DISCOVERY=false` 可跳过），Windows 会弹「未知发布者」，正常。

### 3. 版本号要同步

三处现在是 `0.1.0`：`package.json`、`plugin.yaml`、`app.getVersion()`（读 package.json）。

打包出来的文件名带版本号，`plugin.yaml` 里的版本给 Hermes 看，两者不能分叉。这轮打完先跑一次 `npm run dist` 确认产物名，再决定要不要升到 `0.2.0`（这一轮加了仪表盘、表情、五个模块，按语义化版本够一个小版本了）。

**改版本号单独一条提交**，别混在打包配置里。

## 四、打包后必须实测的（这一步跳过等于没打）

源码版能跑不代表打包版能跑。下面逐条过，每条给结果：

1. **安装**：双击 `dist/hermes-pet-x.x.x-setup.exe`，能选目录、装完开始菜单和桌面有快捷方式
2. **启动不白屏**：桌宠窗口出现，角色立绘正常显示（不是一片空白 —— 这条验的就是 `pixi.min.js` 在 asar 里能不能加载）
3. **基础交互**：能拖、能点四个热区、动作会动、表情会换、气泡说话
4. **面板**：点状态药丸能展开，四组任务列表正常
5. **聊天窗**：能打开、能发一条消息、能收到回复
6. **桥接服务**：`%LOCALAPPDATA%\hermes\hermes-pet-bridge.json` 生成，里面 `port` 和 `token` 都在
7. **Hermes 插件能连**：在 Hermes 里调 `hermes_pet_status`，要能返回打包版的状态（不是源码版的）
8. **开机自启**：菜单里打开，注销重登后桌宠自己起来
9. **退出**：托盘右键退出，进程真的没了（任务管理器确认）
10. **卸载**：控制面板卸载干净，不留 `Program Files` 残目录
11. **便携版**：`hermes-pet-x.x.x-portable.exe` 双击能直接跑，不安装
12. **同时跑两个会怎样**：先启动源码版（`npm start`），再启动装好的版本。单例锁应该让其中一个直接退出；如果不退出，两个会抢同一个桥接文件和端口——`main.js` 里那段注释提过这个风险。**这条必须验**，结果无论好坏都记下来

### 汇报格式

```text
1. npm run dist 的输出（产物路径和体积）
2. du -sh dist/*.exe 各是多少 MB
3. 上面 12 条逐条给过或没过，没验的写原因
4. 打出来的安装包里，node_modules 和 assets 各占多少（electron-builder 会打印，或者解包看 dist/win-unpacked）
5. 版本号最终定成多少、改了哪几处
```

第 2 条和第 4 条是这轮的关键数字：安装包如果能控制在 100MB 以内，说明排除清单生效了；如果接近 200MB，说明 138MB 原始素材漏进了包。

## 五、不许做的

1. **不为了瘦包删运行时素材**。排除清单里那四个目录是先确认「只有 `aligned/` 被引用」才排的，`assets/pet-layers` 和 `assets/hermes-chibi.png` 必须先 grep 确认引用，确认没用到才能排
2. **不改业务代码**。这轮只加打包配置 + 必要的路径适配。如果打包后发现某处路径写死了要改，单独说清楚改的是什么、为什么
3. **不做自动更新**。electron-updater 是下一轮的事，这轮先把「能装能用」打下来
4. **不把 `dist/` 提交进仓库**（`.gitignore` 已有 `dist/`，确认一下）
