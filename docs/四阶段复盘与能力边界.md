# 四个阶段复盘 · 它到底做了什么，现在有什么用

> 这份文档回答两个问题：
> 1. 之前说的「环节 0 / 1 / 2 / 3」分别干了什么，为什么做完之后没有明显反馈；
> 2. 这个东西现在到底有什么用，哪些是能用的，哪些还只是壳。

---

## 一、四个阶段逐条对账

当初规划的四个环节是**做出 2.5D 立体桌宠**的流水线。执行到中途换了实现路线，所以四个阶段的最终归属并不一样，下面逐条写清楚。

### 环节 0 · 调研与规范

| 项 | 内容 |
|---|---|
| 原计划 | 摸清对标对象（DeepSeek 大肥鱼）是怎么做出立体感的，定技术路线与素材规范 |
| 实际做了 | 读了本地 `deepseek-fish-pet` 仓库源码，结论是它**根本没有 3D**：一张平面 PNG + CSS `transform` 挤压拉伸 + 高饱闪烁 + 透明无边框窗口，三样凑出"立体摆件"的错觉；同时拉出 448×841 画布、颈部切缝 y=258、轴心 (224,258)、双眼 x145–303/y152–215 这套坐标规范 |
| 产出 | `docs/对标差距.md`、`docs/Live2D-分层素材规范.md`、坐标表 `assets/pet-layers/meta.json` |
| 当前状态 | ✅ 结论仍在用（坐标表就是现在拆层的依据）；但 Live2D 这条路线**已经放弃** |

**为什么放弃 Live2D**：Cubism Core 有独立授权，官方示例模型不能换成自己的角色；要让赫尔墨兹动起来得先在 Cubism Editor 里手工绑网格——那是一个几天的美术活，不是一晚上的工程活。

### 环节 1 · 立绘分层（拆件）

| 项 | 内容 |
|---|---|
| 原计划 | 把一张立绘拆成可以独立驱动的图层 |
| 实际做了 | 让 AI 生成**同姿势**的差分图（闭眼 / 张嘴，纯绿幕 #00FF00 背景），再用 pngjs 做像素级差分，把眼睛、嘴巴、头部、身体切成四层 |
| 产出 | `assets/pet-layers/` 下 `head.png / eyes.png / mouth.png / body.png` + `meta.json` |
| 当前状态 | ✅ **这是现在整个桌宠的地基**，正在用 |

这一步是四个环节里**唯一完整落地且不可替代**的。关键收益：因为图层来自同一张图的像素差分，天然逐像素对齐，不需要手动调锚点，也不会有错位。

期间踩过的坑：`body.png` 一开始保留了含头部的完整原图，导致歪头时出现"双层轮廓"的虚影；后来改成把头部区域从 body 里挖掉，并对 head 做 9px 柔性扩边，虚影才消失。

### 环节 2 · 表情差分

| 项 | 内容 |
|---|---|
| 原计划 | 生成六种状态（待命/思考/执行/成功/失败/休眠）的表情立绘，用差分图驱动 |
| 实际做了 | AI 重绘了 12 张表情立绘 |
| 结果 | ❌ **失败了**。AI 每次出的图姿势都不一样（头的角度、刘海走向、肩膀位置全变），像素差分根本对不上，硬套会变成"换头"而不是"换表情" |
| 当前状态 | ⚠️ 被**程序化方案替代**：眨眼 = 眼层纵向压缩（锚点在下沿，所以是上眼睑往下压，不是整体缩小）；张嘴 = 嘴层从上唇向下展开；眯眼/闭眼靠同一个压缩系数。这 12 张立绘没浪费，留在 `assets/states/v2/` 当静态状态图用 |

**这条是"为什么做完没反馈"最直接的答案**：这个环节产出的东西最后没进渲染链路，等于空转。当时的做法是直接换方案继续往下走，没有回头告诉你这一步废了。

### 环节 3 · 运行时接入

| 项 | 内容 |
|---|---|
| 原计划 | 把分好的图层接进 Electron，让角色真的能动 |
| 实际做了 | 自研渲染层 `renderer/pet-puppet.js`（PixiJS），四层驱动 + 六态参数表（倾角/纵向偏移/眼睛开合/嘴部开合/呼吸强度/身体侧倾）+ 眨眼调度 + 视线跟随 + 口型节奏 + 呼吸 + 热区互动 |
| 产出 | 一个能歪头、能眨眼、能看你鼠标、能说话动嘴的角色 |
| 当前状态 | ✅ 在用；本次更新又补了透视与投影（见下） |

### 一句话总结

| 环节 | 干了什么 | 现在还有用吗 |
|---|---|---|
| 0 | 调研 + 定规范 | 规范有用，Live2D 路线废弃 |
| 1 | 拆图层 | ✅ 核心地基 |
| 2 | AI 表情差分 | ❌ 失败，被程序化眼睑替代 |
| 3 | 渲染与交互 | ✅ 在用，本次继续加强 |

**"为什么没有具体反馈"的诚实回答**：环节 2 失败后我直接换了方案往下做，没有停下来告诉你"这条路走不通、我改用另一条"，所以你看到的是一串没有结论的动作。这是流程问题，不是能力问题。

## 二、本次新增的「立体化」（补充环节 3）

对标结论是"大肥鱼的立体感是假的"，那真立体感从哪来？三条物理线索：**透视、遮挡、投影**。这次补的就是这三样。

| 做法 | 原来 | 现在 |
|---|---|---|
| 投影 | 没有，角色像贴在屏幕上 | 脚底加了软边椭圆投影（`assets/pet-layers/shadow.png`），随呼吸起伏、跳跃时缩小变淡 |
| 落地空间 | 角色脚底贴着窗口边缘 | 脚下留出 9–14px 屏幕空间，影子有地方落 |
| 转头透视 | 只有旋转 | 转头时头部沿 X 轴压扁（cos 效应）+ 轻微斜切，平面的脸开始有体积 |
| 对立式 | 头动身子跟着平移 | 头往左看、身体微往右，像真的在转身而不是整体平移 |
| 挤压守恒 | 只有纵向呼吸 | 纵向拉伸时横向同步压缩，重心起伏更像活人 |

验收方式：`node tools/preview-pet.js` 会输出一张「正面 / 向右看 / 向左看」的三视角对比图。

## 三、它到底有什么用

分两类说，**能用的**和**还不能用的**，不粉饰。

### 真正能用的（每天都在生效）

| 能力 | 具体是什么 | 触发方式 |
|---|---|---|
| 状态可视化 | 桌宠头顶胶囊实时显示「在线 · N 个在跑」，角色动作跟着 Hermes 变（待命/执行中/思考/成功/失败/休眠） | 自动，3 秒轮询 |
| 结果播报 | 任务完成、受阻、失败会弹气泡 + 系统通知，角色切对应表情 | 自动 |
| 离线提醒 | Hermes 服务断了 / 回来了会各说一句 | 自动 |
| 派任务 | 把文件拖到角色身上 → 填标题 → 直接变成 Hermes 看板上的任务（附件一起上传） | 拖拽 |
| 聊天 | 对话窗直接和 Hermes 的 Bot Chat 会话对话，共享同一条上下文 | `Ctrl + Shift + H` |
| 看记忆 / 技能 | 只读展示 Hermes 的 `USER.md`、`MEMORY.md` 和已装技能 | 对话窗按钮 |
| 语音播报 | 用系统离线语音念出来，不消耗 API 费用 | 设置里开 |
| 陪伴层 | 摸头有反应（爱心 + 台词）、心情/好感随互动变化、闲时主动说话 | 悬停/点击 |

### 还不能用的（明确的边界）

| 缺什么 | 现状 |
|---|---|
| 细粒度审批 | 免打扰里只有「审批/需协助提醒仍出声」一个总开关，没有白名单——不能指定「只有这类操作才叫我」 |
| 任务播报粒度 | 只播「完成/受阻/失败」三种，不会逐条播进度 |
| 记忆写入 | 记忆面板只读，不能在桌宠里改 Hermes 的记忆 |
| 3D 模型 | 现在是"分层 2D + 立体化运动"，不是真 3D 网格模型（原因见下） |
| Hermes 启动时自动拉起 | **没有**。桌宠只有「开机自启」（系统登录时启动），Hermes 启动不会带起它 |

### 关于「做成 3D」

真正的 3D 需要一份 GLB/VRM 网格模型，而赫尔墨兹现在只有立绘。三条路：

| 路线 | 代价 | 效果 |
|---|---|---|
| AI 图生 3D（Tripo / Meshy 等） | 需要积分与网络，单张正面图转 3D，背面靠猜 | 二次元角色容易形变，头发和披风散成片，多需返工 |
| VRoid / Blender 手工建模 | 至少几十小时 | 可控、可做骨骼动画，是长期正解 |
| 分层 2D + 立体化（当前） | 零素材成本 | 转动/呼吸/投影/透视都有了，**不动模型也能拿到大部分立体感** |

结论：先用第三条把"活着的立体感"做足，真 3D 模型作为独立任务另开，不塞进日常优化里。

## 四、生命周期：开机、关机、Hermes 启停之后它怎么存在

这是最容易被忽略、也最容易让人觉得"它到底在不在"的一块。

```
Windows 登录
   │
   ├─ 如果开了「开机自启」→ 桌宠进程启动 → 托盘常驻 + 桌面上出现角色
   │
   └─ 如果没开 → 什么都不会发生，需要手动启动

Hermes 启动 / 关闭
   │
   ├─ 桌宠只做轮询：启动后 3 秒内发现 Hermes 在线 → 胶囊变绿、开始同步任务
   └─ Hermes 关闭 → 胶囊变灰「Hermes 离线」，角色进入待命，
                    其余功能（聊天、派任务、记忆）全部不可用，但角色仍在桌面上

关闭窗口（× 或 —）
   │
   └─ 只是隐藏，进程还活着，托盘图标还在（右键托盘 → 显示 / 退出）

真正退出
   │
   ├─ 右键角色 → 退出
   └─ 托盘右键 → 退出
```

三个要点：

1. **它和 Hermes 是两个独立进程**。Hermes 关了它不会跟着退出（只是变离线），它退出了 Hermes 也照常工作。
2. **关窗口 ≠ 退出**。点 × 只是收起来，进程留在托盘，状态还在同步。
3. **只有「开机自启」没有「跟着 Hermes 启动」**。想让它在 Hermes 起来时出现，现在的做法是开着开机自启，让它一直在托盘里等着。
