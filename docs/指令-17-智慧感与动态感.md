# 第一批：智慧感

## 1.1 现在的问题：存了记忆，但从来不喂给模型

查证过：`memory.js` 有 `updateMidterm`（中期摘要）、`snapshot`（长期归档）这些能力，但 `main.js` 里 `petMemory` 只被调了两处——`record`（写）和 `archive`（归档给界面看），**一次都没有进过 prompt**。

所以 `askModel` 的 system prompt 现在只有这三行（`main.js:240-243`）：

```js
const system = `${settings.persona}
主人称呼：${settings.userName}。
你是桌宠，不要声称自己已经执行了电脑操作。当前状态：${petState.statusText}；心情：${petState.mood}/100；好感度：${petState.affection}/100。
回答要短、具体、像熟悉主人的桌面伙伴。除非主人要求，不要输出 Markdown 标题，不要复述问题。`;
```

**它不知道**：现在几点、在跑什么任务、有几个等你验收、昨天聊过什么、上次说话是多久以前。

这就是「不够聪明」的全部原因。不是模型不行，是它瞎着。

## 1.2 改法：把上下文拼进去

新增一个 `buildContext()`，放在 `pet-state.js` 或 `main.js` 都行（建议 `pet-state.js`，它已经能访问全部状态）：

```js
function buildContext(now = new Date()) {
  const s = state;
  const lines = [];

  // 时间感：凌晨和下午说话的语气不一样
  const hh = now.getHours();
  const period = hh < 5 ? '凌晨' : hh < 11 ? '早上' : hh < 14 ? '中午' : hh < 18 ? '下午' : hh < 23 ? '晚上' : '深夜';
  lines.push(`现在是 ${period} ${hh}:${String(now.getMinutes()).padStart(2, '0')}。`);

  // 任务感：桌宠最该知道的是「他在忙什么」
  if (s.currentTask?.title) {
    lines.push(`主人手上正在做：「${s.currentTask.title}」${s.currentTask.assignee ? `，由 ${s.currentTask.assignee} 执行` : ''}。`);
  }
  const q = s.queue || {};
  const pending = [];
  if (q.review) pending.push(`${q.review} 个等验收`);
  if (q.blocked) pending.push(`${q.blocked} 个卡住`);
  if (q.running) pending.push(`${q.running} 个在跑`);
  if (pending.length) lines.push(`看板：${pending.join('，')}。`);
  else lines.push('看板是空的，现在没有活。');

  // 关系感：好感度影响亲疏
  if (s.affection >= 80) lines.push('你和主人很熟，可以随意一点，偶尔拆个台。');
  else if (s.affection <= 30) lines.push('主人最近不怎么理你，稍微收敛一点，别太热络。');

  // 上次聊天隔了多久
  const gapMin = Math.round((now.getTime() - (s.lastInteraction || now.getTime())) / 60000);
  if (gapMin > 180) lines.push(`主人已经 ${Math.round(gapMin / 60)} 小时没理你了。`);
  else if (gapMin > 20) lines.push(`主人 ${gapMin} 分钟没动静了。`);

  return lines.join('\n');
}
```

`askModel` 里：

```js
const system = `${settings.persona}
${context}
主人称呼：${settings.userName}。
你是桌宠，不要声称自己已经执行了电脑操作。
当前状态：${petState.statusText}；心情：${petState.mood}/100；好感度：${petState.affection}/100。

回答规则（重要）：
- 控制在 30 字内。能一句话说完就不要两句。
- 可以表达偏好和情绪，不要什么都答应。被问到不想做的事，直接说不想。
- 不要复述主人的问题，不要说「好的」「明白了」这类应答词。
- 除非主人要求，不要输出 Markdown、不要列条目。`;
```

`petMemory.snapshot(root)` 返回什么先看清楚（`memory.js:120`），把最近 3 天的中期摘要拼进 context：

## 1.4 主动说话：从抽签改成基于状态的判断

`renderer/pet.js:589-598` 现在是：

```js
setInterval(() => {
  ...
  const chance = lineFrequency === 'chatty' ? 0.55 : 0.25;
  if (Math.random() > chance) return;
  sayAddressed(LINES[Math.floor(Math.random() * LINES.length)], 3600);
}, 90000);
```

死台词 + 抛骰子。改成两组：

**A. 有事说事（优先级最高，不看概率）**

在 `paintState` 里加状态边沿检测（`hermes-poller` 的 `reviewTransitions` 已经在做主进程侧的边沿，渲染层这里只看 `petState` 的变化）：

```js
let lastSpokenState = {};
function maybeSpeakByState(s) {
  const prev = lastSpokenState;
  // 有新任务等你验收
  if ((s.queue?.review || 0) > (prev.queue?.review || 0)) {
    sayAddressed(`{address}，${s.queue.review} 个做完了，等你验收`, 4200);
  }
  // 有任务卡住
  else if ((s.queue?.blocked || 0) > (prev.queue?.blocked || 0)) {
    sayAddressed('{address}，有活卡住了，得你去看一眼', 4200);
  }
  // 全部干完
  else if ((prev.queue?.running || 0) > 0 && (s.queue?.running || 0) === 0) {
    sayAddressed('{address}，都干完了', 3200);
  }
  lastSpokenState = JSON.parse(JSON.stringify(s));
}
```

**B. 没事闲聊（降低频率，内容要跟时间有关）**

把 `LINES` 里那 20 条固定台词换成分时段的池子：

```js
const IDLE_LINES = {
  dawn:   ['这个点还没睡', '天亮前最安静，适合干活'],
  morning:['早，今天排了不少事', '睡醒了吗'],
  noon:   ['吃过饭没有', '中午了，别硬撑'],
  afternoon: ['下午容易困，我能陪你说两句', '这半天过得挺快'],
  evening:['天黑了，要不要收个尾', '晚上安静，适合清活'],
  late:   ['都这个点了，该睡了', '再熬下去明天崩']
};
```

`sayAddressed` 时按当前 `Date` 的小时数选池子。**这比随机抽 20 条死台词更像活的。**

同时把 `chatBusy`、`bubbleVisible`、`dragging` 的守卫保留，别在用户说话时插嘴。

# 第二批：大肥鱼那种动态感

## 2.1 先看清差距在哪

对照过 README 里那段对标结论（`README.md:224`）和大肥鱼的关键帧：

```css
/* 大肥鱼的 bounce */
0%   { transform: scale(1); }
25%  { transform: scale(.9, .84) translateY(-6px); }   /* 压扁 16% */
50%  { transform: scale(1.08, 1.1) translateY(2px); }  /* 拉开 10% */
75%  { transform: scale(.97, 1.03); }
100% { transform: scale(1); }
```

现在项目的 `breathe`：

```css
0%   { transform: translateX(-50%) translateY(0) scale(1); }
25%  { transform: translateX(-50%) translateY(-2.4px) scale(1.02); }
50%  { transform: translateX(-50%) translateY(-1px) scale(1); }
75%  { transform: translateX(-50%) translateY(0.6px) scale(0.98); }
100% { transform: translateX(-50%) translateY(0) scale(1); }
```

**结论：挤压拉伸的"形变量"项目其实够了**（`quickHop` 有 `scale(.96,1.06)`、`jellyBounce` 有 `scale(1.06,.9)`，跟大肥鱼一个量级）。

差的是下面四件事，都不用新素材，纯 CSS/JS：

## 2.2 差距一：动作收尾没有余震

现在每个动作的 `@keyframes` 最后都回到 `transform: scale(1)`，是**硬回位**。大肥鱼的动作结束会有一次小小的过冲再回稳。

改法：给所有位移/形变类动作的 100% 前插一个过冲帧。以 `quickHop` 为例：

```css
@keyframes quickHop {
  0%   { transform: translateY(0) scale(1); }
  24%  { transform: translateY(-14px) scale(.96, 1.06); }   /* 起跳拉长 */
  54%  { transform: translateY(2px) scale(1.05, .93); }     /* 落地压扁 */
  74%  { transform: translateY(-2px) scale(.99, 1.01); }    /* 一次小回弹 ← 新增 */
  100% { transform: translateY(0) scale(1); }
}
```

**15 个动作里凡是带 `translateY` 或 `scale` 的，都插一个 70%~80% 的过冲帧**，幅度约为峰值的 15%。这条做完，观感立刻从「播放一段动画」变成「有重量地动了一下」。

## 2.3 差距二：待机动作太稀疏

`renderer/pet.js:386-395`：

```js
function idleLoop() {
  const wait = 6000 + Math.random() * 7000;   // 6~13 秒
  ...
}
```

用户盯着看 30 秒，可能只看到两三次动作。大肥鱼的小动作接近连续。

改法两条一起：

1. **间隔缩短到 3.5~8 秒**
2. **加权随机**：别 15 个动作等概率，让「小动作」出现得更频繁

```js
// 待机时大幅度的跳/挥臂不该频繁出现，小动作才是"活着"的信号
const IDLE_WEIGHTS = {
  'double-blink': 5, 'look-away': 5, 'slow-yawn': 2, 'curious-peek': 4,
  'heel-tap': 3, 'side-brace': 2, 'jelly-bounce': 1, 'quick-hop': 1,
  'cheer': 1, 'sparkle-cast': 1, 'hat-check': 2, 'soft-lean': 3,
  'proud-bow': 1, 'cape-flick': 2, 'stumble': 1
};
function pickIdleAction(previousId) {
  const entries = Object.entries(IDLE_WEIGHTS).filter(([id]) => id !== previousId);
  const total = entries.reduce((sum, [, w]) => sum + w, 0);
  let roll = Math.random() * total;
  for (const [id, w] of entries) {
    roll -= w;
    if (roll <= 0) return id;
  }
  return entries[0][0];
}
```

## 2.4 差距三：没有「被鼠标撞到」的反应

现在鼠标移动只做视线跟随（`main.js` 里监听 `mousemove` 写 `--look-x/--look-y`）。大肥鱼会躲、会抖。

改法：在渲染层加速度检测，快掠过时抖一下：

```js
let lastMouse = null;
let lastJoltAt = 0;
window.addEventListener('mousemove', (e) => {
  const now = Date.now();
  if (lastMouse) {
    const dt = Math.max(1, now - lastMouse.t);
    const speed = Math.hypot(e.clientX - lastMouse.x, e.clientY - lastMouse.y) / dt;  // px/ms
    // 快速掠过（>1.8 px/ms）且 1.2 秒内没抖过，才触发，避免连抖
    if (speed > 1.8 && now - lastJoltAt > 1200 && !dragging && !bubbleVisible()) {
      lastJoltAt = now;
      jolt();
    }
  }
  lastMouse = { x: e.clientX, y: e.clientY, t: now };
});

function jolt() {
  // 往鼠标反方向缩一下，然后弹回，140ms 一次，别拖泥带水
  const dir = lastMouse.x < window.innerWidth / 2 ? 1 : -1;
  gestureEl.style.setProperty('--jolt-x', `${dir * 3}px`);
  gestureEl.classList.remove('jolt');
  void gestureEl.offsetWidth;
  gestureEl.classList.add('jolt');
  setTimeout(() => gestureEl.classList.remove('jolt'), 150);
}
```

```css
@keyframes jolt {
  0%   { transform: translateX(0) scale(1, 1); }
  35%  { transform: translateX(var(--jolt-x, 3px)) scale(.985, 1.015); }
  70%  { transform: translateX(calc(var(--jolt-x, 3px) * -.4)) scale(1.01, .99); }
  100% { transform: translateX(0) scale(1, 1); }
}
#pet-gesture.jolt { animation: jolt 140ms ease-out; }
```

**注意 `#pet-gesture` 已经承载 `gesture-active`**，`jolt` 和它同时存在会打架。所以 `jolt` 要加判断：`gesture-active` 在场时不抖。

## 2.5 差距四：头和身子没有延迟差

真实生物动的时候，头和身子不是同时到位的。现在整张图是一起动的。

可以用现有的四层结构做假延迟：

```text
#pet           breathe
  #pet-state    状态动画
    #pet-gesture  动作动画（现在整张一起动）
      #pet-inner    视线偏移
```

改造：让 `#pet-inner` 在 `#pet-gesture` 播动作时，做一个**延迟 60ms、反向 30%** 的补偿：

```js
function playAction(group) {
  ...
  gestureEl.classList.add('gesture-active');
  // 头比身子早 60ms 到位，身体再跟上来，才有"软"的感觉
  petInner.style.transition = 'none';
  petInner.style.transform = 'translateY(2px) scale(1.006, .994)';
  setTimeout(() => {
    petInner.style.transition = 'transform 220ms cubic-bezier(.34, 1.56, .64, 1)';
    petInner.style.transform = 'translateY(0) scale(1, 1)';
  }, 60);
}
```

**但 `#pet-inner` 已经有 `transform: translate(var(--look-x), var(--look-y))`**（视线偏移），直接写 `style.transform` 会覆盖视线。

所以要么用 CSS 变量叠加，要么在 `#pet-inner` 里再套一层 `#pet-inner-b` 专管这个。**建议后者，一层一个职责**——这是这个项目已经验证过的原则。

# 执行顺序与硬约束

1. **先做第一批**。智慧感的改动最小、效果最明显，而且改动集中在 `askModel` 和 `renderer/pet.js`，不碰视觉层，出问题好回滚
2. **第二批（动态感）单独立提交**。它改 `style.css` 和 `pet.js` 的动画部分，和第一批不重叠
3. **第三批随时可以插**，都是低风险改动

不许做的：

1. **不要为了动态感把呼吸幅度拉到 10% 以上**。`breathe` 是「呼吸」，2% 是对的；大肥鱼那个 16% 是「弹跳」，已经由 `quickHop`/`jellyBounce` 承担了。混在一起会像抽搐
2. **不要在 `#pet-inner` 上直接写 `style.transform`**，它已经有视线偏移的 CSS 变量
3. **`jolt` 不能和 `gesture-active` 同时播**，会抢 `animation` 属性
4. **prompt 里的 context 控制在 300 字内**，别把 16 条对话历史挤掉
5. **主动说话的守卫不能删**（`dragging` / `bubbleVisible` / `chatBusy`）
