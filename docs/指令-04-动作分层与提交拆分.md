## 二、三个必须先修的问题

### 问题 1（严重）：动作动画把待机呼吸顶掉了

`renderer/style.css:103`

```css
#pet {
  animation: breathe 3.6s cubic-bezier(.37, 0, .63, 1) infinite;
}
```

`renderer/style.css:267` 起

```css
#pet.gesture-head { animation: gestureHead .9s cubic-bezier(.2, .8, .25, 1); }
```

`#pet.gesture-head` 特异性（0,2,0）高于 `#pet`（0,1,0），而且 `animation` 是简写属性——**加 class 的瞬间 `breathe` 被整条覆盖掉**。

实际表现：

1. 点一下头 → 呼吸停，只剩 `gestureHead` 的旋转
2. 1100ms 后 `petEl.classList.remove('gesture-head')` → `animation` 回落成 `breathe`，**从 0% 重新计时**
3. 每点一次，呼吸节奏被重置一次

更麻烦的是 `#pet` 底下还挂着 `#pet-fx`（特效层）和 `#pet-hit-area`（热区），在 `#pet` 上做动作 transform，**粒子特效和热区会跟着一起晃**。

**改法**：动作必须和呼吸分成两层独立的 transform。

`renderer/index.html:25-33` 现在是这样：

```html
<div id="pet" aria-label="赫尔墨兹桌宠">
  <div id="pet-live2d-host"></div>
  <div id="pet-inner"> ... 图层 ... </div>
  <div id="pet-hit-area" aria-hidden="true"></div>
  <div id="pet-fx" aria-hidden="true"></div>
</div>
```

改成在 `#pet` 和 `#pet-inner` 之间插一层 `#pet-gesture`：

```html
<div id="pet" aria-label="赫尔墨兹桌宠">
  <div id="pet-live2d-host"></div>
  <div id="pet-gesture">
    <div id="pet-inner"> ... 图层 ... </div>
  </div>
  <div id="pet-hit-area" aria-hidden="true"></div>
  <div id="pet-fx" aria-hidden="true"></div>
</div>
```

分工写成硬规则：

| 层 | 负责 | 谁写它的 transform |
|---|---|---|
| `#pet` | 待机呼吸 `breathe` | 只有 `breathe` |
| `#pet-gesture` | 7 组动作动画 | 只有 `gesture-*`，平时无 animation |
| `#pet-inner` | 视线偏移 | 只有 `--look-x/--look-y` |
| `#pet-fx` | 粒子特效 | 不动 |

`#pet-gesture` 要补 `position: absolute; inset: 0; transform-origin: 50% 96%;`（和 `#pet` 同一个原点，否则旋转轴心会偏）。
`PlayAction` 里所有 `petEl.classList.add/remove('gesture-*')` 和 `petEl.dataset.action` 一并改挂到 `#pet-gesture`。
`#pet-live2d-host` 现在直接挂在 `#pet` 下，不受 gesture 影响，这是对的——Live2D 模式另有自己的渲染循环，别把它挪进新层。

顺带说明为什么不能简单地在 `#pet` 上写两条 animation：

```css
#pet { animation: breathe 3.6s infinite, gestureHead .9s; }  /* 不成立 */
```

两条 animation 都在写 `transform`，CSS 同一属性后写的赢，等于 `breathe` 静默失效。**同属性必须分层，不能并联。**

### 问题 2：`gesture-idle` 动画被定时器截断

`renderer/style.css:271` 和 `renderer/pet.js:367-370`

```css
#pet.gesture-idle { animation: gestureIdle 1.15s ease-in-out; }
```

```js
gestureTimer = setTimeout(() => {
  petEl.classList.remove(`gesture-${group}`);
  delete petEl.dataset.action;
}, 1100);
```

定时器 1100ms，动画 1150ms —— 待机/撒娇/魔法三组里最长的那段**永远播不完，差 50ms 被掐断回弹**。这类"看着卡一下"的观感问题在实机上比数值差更容易被察觉。

**改法**：别让两处各写一个数字。在 `pet-actions.js` 的动作表里把 `duration` 作为配置项，`style.css` 用变量读，`playAction` 用同一个值设定时器：

```js
// pet-actions.js
// duration 和 style.css 里的动画时长必须同源，否则定时器会掐掉动画尾巴
const ACTIONS = [
  ['head', 'hat-check', 'sweat', 900],
  ...
].map(([group, id, effect, duration], index) => ({ group, id, effect, duration, index }));
```

```css
#pet-gesture.gesture-head { animation: gestureHead calc(var(--gesture-ms, 900) * 1ms) cubic-bezier(.2, .8, .25, 1); }
```

```js
const timer = setTimeout(cleanup, action.duration + 60);  // +60ms 兜住渲染帧差
```

或者更省事的做法：**定时器一律用 `animationend` 事件**，不猜时长：

```js
gestureEl.addEventListener('animationend', () => { clearGesture(); }, { once: true });
```

推荐后者。猜数字这件事，现在只错了一处，扩到 28 个动作后就会错一片。

`@media (prefers-reduced-motion: reduce)` 那段（`style.css:444-448`）把时长压到 `.01ms` 是正确的，但配 `animationend` 时要防住"降级下事件不来"，加一个兜底 `setTimeout`。

### 问题 3（设计层）：28 个动作实际是 7 个动作 × 4 档力度

`pet-actions.js` 里 28 条记录，`group` 只有 7 种；`style.css` 也只定义 7 段 `@keyframes`。每个动作的差异全在这两行：

```css
#pet[data-action="quick-hop"]  { --gesture-tilt: -3deg; --gesture-rise: -13px; }
#pet[data-action="dance-step"] { --gesture-tilt: -6deg; --gesture-rise: -5px; }
```

同组的 `jelly-bounce` / `tiny-twirl` / `cape-flick` 播的是同一段 `gestureBody`，只差 3 度旋转和 4px 位移。用户点脸和点身体，看到的是同一套晃动换个力度——**"28 个动作"这个数字目前名不副实**。

两条路，选一条，别两条都浅做：

**A. 保住 28，把差异做真（改 4 个地方，成本中等）**

同组动作要在下面四项里至少分开两项，不能只动 tilt/rise：

| 维度 | 做法 |
|---|---|
| 幅度与方向 | `--gesture-tilt` / `--gesture-rise` 之外补 `--gesture-scale`（挤压量）、`--gesture-shift`（横向） |
| 节奏 | 每个动作独立 `animation-duration` + `animation-timing-function`（`jelly-bounce` 用弹性 `cubic-bezier(.34,1.56,.64,1)`，`side-brace` 用干脆的 `ease-out`） |
| 配件层 | `cape-flick` 动披风、`hat-check` 动帽子、`mark` 动脚底影子——`#pet` 下已有分层素材，让配件层错开 80~120ms 起播 |
| 特效时机 | 现在 `spawnActionEffect` 是动作一开始就撒粒子；`quick-hop` 这类该在落地帧（约 55%）才出 `dust` |

**B. 收敛到 12 个真不同的（成本最低，最诚实）**

4 个热区各 3 个动作 + 待机/撒娇/魔法共 3 个。台词表按区域×情绪，不依赖 28 个 id，收敛不会破坏现有 `persona.json` 结构，删 id 即可。

**我建议选 B**，理由：A 要补 4 个维度、28 组参数，改完还得逐个肉眼验；B 落地当天就能看效果，而且 12 个真动作比 28 个假动作更像"活着"。等 B 稳定了，将来想扩再从 12 加到 20，加的是真动作。

这条需要用户拍板，**你先别自作主张动手**，把 A/B 的成本和效果各写一段摆出来，等回复。

## 三、改完的验收方式

`npm test` 只跑纯逻辑（`pet-actions`、`pet-interactions` 的返回值），**证明不了动作好不好看、有没有被截断**。这次必须实机验：

```bash
npm start
```

按顺序点一遍，每条给结论：

1. 头、脸、身体、脚各点 3 次 → 同一区域三下动作要能看出差别，不能是同一段动画换个力度
2. 点完立刻松手，**呼吸有没有停一下再重新开始** → 有问题说明问题 1 没修干净
3. 待机等 30 秒 → 随机动作要完整播完再回待机，不能半路回弹（问题 2）
4. 开系统"减少动态效果"再点 → 动作应当降级但不报错、不卡住
5. 拖到屏幕边上再点 → 特效粒子不能飞出窗口边界外被裁掉一半
6. 顺手实点复核四区热区坐标（README「已知未做」里挂着这条）

截 3 张图存到 `docs/` 下（或贴路径），比文字描述管用。


- `renderer/pet-puppet.js`（眨眼 58→95ms、周期 2800→3000+5000、呼吸 1080→570、横向 2700→1900）

拆之前先跑 `git diff --check` 和 `git diff -U0 <file>` 确认 hunk 边界，两个混合文件用 `git add -p` 逐块挑。**提交 1 先落，提交 2 后落**，顺序反了会先动呼吸节奏，动作差异的判断基准就变了。
