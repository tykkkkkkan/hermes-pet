# 赫尔墨兹 · 立绘素材规格（V2 · 完整版）

> 上一版只写到「8 张图够不够用」。这一版写到「怎么做到和大肥鱼一样活」。
> 分三层交付，你按自己产能挑，越往下越接近终极形态。

## 零 · 总纲

| 层 | 数量 | 得到什么 | 工作量 |
|---|---|---|---|
| **T1** | 8 张 | 桌宠能看、能切状态、会累会气会庆祝 | 一次出图 |

## 一 · T1：八个状态姿势（必做）

### 统一的角色描述块

每张提示词开头都要粘同一段，**只改括号里的姿势**。这段必须逐字一致，否则 AI 会当成两个角色。

```
同一角色的全身立绘：银白色长发、[发饰细节]、[瞳色]眼睛、
白色连衣裙（[裙摆层数与褶边细节]）、[翅膀/羽翼细节]、[鞋袜]。
画风与原图完全一致，赛璐璐上色，主光来自左上方，阴影落向右下。
纯透明背景，不要地面、不要投影、不要边框、不要任何背景元素。
```

> 括号里的细节**按你手上的 01 号原图填**。填得越具体，一致性越高。我看不到原图的全部细节，必须你来补。

### 八张的具体构图

每张都要求：**正面朝向、双脚在画布底部、头顶不超出画布 5%**。

| # | 文件名 | 姿势 | 具体描述（替换到提示词里） | 切到这个状态的时机 |
|---|---|---|---|---|
| 1 | `idle.png` | 站 | 正面站立，双手自然垂在身侧，重心居中，双脚并拢略分开，头正，嘴角微笑，裙摆自然下垂 | 默认常驻 ✅**已有 01 号，可复用** |
| 2 | `thinking.png` | 托腮 | 正面略微偏头，右手抬起托住脸颊（手肘支起），左手轻抱在身前，头微低 5°，视线下垂不看镜头，眉毛微蹙，一侧头发滑落 | Codex 推理中、Agent 思考 |
| 3 | `working.png` | 干活 | 正面，身体前倾，双手在身前抬起作敲击状（手腕下垂、手指微弯），头略低，眼神专注向下，肩膀内收 | 正在执行命令、跑编译 |
| 4 | `waiting.png` | 等你 | 正面，左手抬起在胸前（掌心向上，像递东西或提醒），右手自然下垂，头正略偏，眼睛睁大、表情期待，身体微微前倾 | 等你确认、等你回话 |
| 5 | `success.png` | 庆祝 | 正面，双臂上举成 V 形，双脚离地腾空，头微仰，眼睛笑成弯月，张嘴大笑，头发与裙摆向上扬起 | 任务完成、测试通过 |
| 6 | `error.png` | 失败 | 正面，双肩塌下，头低 15°，双手无力垂下，眉头下撇成八字，嘴角下弯，额头一滴汗，头发下垂无动态 | 报错、卡住、超时 |
| 7 | `sleepy.png` | 困 | 正面，右手手背贴右眼作揉眼状，左手垂下，头略歪，嘴巴张大打哈欠，双眼只剩一条缝，身体向一侧微倾 | 长时间无操作、深夜 |
| 8 | `annoyed.png` | 不满 | 正面，双手叉腰，双脚略分开站，头正，眼睛半眯瞪视，眉毛倒竖，脸颊鼓气，发梢有轻微翘起 | 被反复拖拽、被戳太多 |

### 为什么这 8 个，不是 9 个 10 个

它们对应 `dsh_state.py` 里的八状态收敛模型（idle / thinking / working / waiting / success / error + 疲劳态 + 交互态）。**状态数决定图数，不是表情数。** 表情多了没用，因为桌宠只有 350–450px，纯换脸在这个尺寸看不出来，只有姿势变化能被感知。

## 二 · T2：眨眼与走路（强烈建议，+3 张）

这一层是"贴图"和"活的"的分界线。**成本极低，观感提升最大。**

### 2.1 眨眼：`idle-blink.png`

**和 `idle.png` 完全一样的身体**，只把眼睛换成闭眼（两条下弯的弧线）。

要求严格到近乎苛刻：
- **身体每一个像素都不动**：手臂角度、裙摆褶皱、发丝走向，全部与 `idle.png` 一致
- 只改眼睛区域
- 眉毛、嘴角**不变**

如果 AI 做不到"其他完全不动"，退一步的做法是：只要眼睛是闭的、身体姿态一致即可，我这边会做差分遮罩只取眼部区域。

**为什么值得单独出一张**：有了它，桌宠每 3–6 秒眨一次眼，立刻从"图片"变成"有生命的东西"。这是所有桌宠最关键的一个动画。

### 2.2 走路：两张关键帧

走路不需要很多帧，**两个关键帧 + 程序镜像**就能循环：

| 文件名 | 描述 |
|---|---|
| `walk-contact.png` | 正面，左脚向前迈出（膝盖微屈，脚尖点地），右脚在后，重心偏右，身体略向左倾，双臂前后自然摆动（左臂在前、右臂在后），裙摆有向前飘动 |
| `walk-pass.png` | 正面，双脚并拢（正在经过的中姿态），重心在正上方，身体直立并比平时略高，双臂贴近身体自然下垂，裙摆回落 |

有了这两张，循环是：`contact → pass → contact(水平翻转) → pass → …`，四帧循环。加上程序的窗口位移（我从大肥鱼的 `move_strides.json` 里拿到了 `stride` + `curve` 位移曲线算法），就能走出「脚在迈、人在移动」的效果。

**前提**：你的角色要左右基本对称。翅膀如果是不对称设计，翻转后会露出破绽，那就需要再补一张右迈版本。

### 2.3 （可选）`drag.png`

被拖拽时悬空：双手举起过头（被拎住的感觉），双脚自然垂下并微微摆荡，表情惊讶，头发和裙摆向上飘。

只有一张，但它是"手感"的关键——拖拽时如果还是站姿，会像拖一张贴纸。

## 三 · T3：转向（可选，收益有限）

| 文件名 | 描述 |
|---|---|
| `side.png` | 完全侧面（朝右），站立，双手身前交叠 |
| `back.png` | 完全背面，站立，能看到后发与翅膀的背面 |

**实话**：静态图做转身只能用硬切（正面→侧面→背面瞬间换），中间没有过渡帧，看起来会"闪"。除非每个朝向都出 3 帧过渡，成本翻三倍。所以这一层**先不做**，等 T1/T2 跑起来再评估。

## 四 · 硬规格（六条，缺一则切图会跳）

| 项 | 要求 | 违反了会怎样 |
|---|---|---|
| **画布** | 1024 × 1024 或更大，**正方形** | 非正方形会导致比例失真 |
| **格式** | PNG，**透明背景**（alpha 通道） | JPG 没有透明，抠图边缘会带白边 |
| **脚底位置** | 统一在**距底 5%** 处 | 脚底不固定 → 切换时人物上下窜 |
| **水平位置** | 身体中轴统一在**正中** | 不居中 → 左右跳 |
| **头顶余量** | 头顶最高点**不低于距顶 5%** | 跳跃/举手的姿势会被裁掉手和头发 |
| **视角** | 全部**正面**，不侧身、不俯仰 | 视角变了就是另一个人 |

### 关于"角色占多高"

不用精确控制成 80%。你只要满足上面三条（脚底 5%、中轴正中、头顶留 5%），**实际身高我会按每张图的内容包围盒自动算出来，再统一缩放到同一基准**。

`tools/build-pet-3d.js` 已经在做这件事——它会算出每张图的真实脚底和头顶位置，重新对齐。所以画面里的人偏左一点、偏上一点、大一点小一点，都没关系。

**你只需要保证角色本身画得一致。**

## 五 · 出图约束（不要做什么）

| ❌ 不要 | 原因 |
|---|---|
| **拼图**（多张挤一张，像之前的 3×2 宫格） | 压缩互相污染，拆格容易把分隔线判进角色 |
| **加投影 / 地面 / 倒影** | 影子由程序按桌面动态生成，画死的影子换壁纸就露馅 |
| **加描边 / 发光 / 外发光** | 破坏 alpha 边缘，抠图会出毛刺 |
| **加背景（哪怕纯白或纯绿）** | 要真透明，不是"看起来透明" |
| **自己降噪 / 锐化 / 压缩** | 我这边做统一清晰度处理，你处理过的会叠加失真 |
| **加文字标签** | 之前 6 张动作图带手写标题，那种不能当立绘用 |
| **裁到画布边缘** | 举手、跳跃的姿势会被切断 |

## 八 · 我这边会做什么

拿到图后我跑：

```
node tools/build-pet-3d.js
```

自动完成：
1. 逐张算内容包围盒 → 得到真实身高与脚底位置
2. 统一缩放到同一基准（角色高 80%、脚底 0.95、中轴 0.5）
3. 清理 AI 出图常见的底残留（腿缝白楔、脚下白影子）
4. 立体化：清晰度 + 凹陷遮蔽 + 暗部边缘光 + 饱和度补偿
5. 生成对应的落影 / 贴地影 / 泛光图层
6. 更新 `manifest.json` 的锚点与状态映射

**然后出一张 8 张并排的对比图**，你一眼能看出哪张跳位、哪张风格偏了。

## 九 · 如果做到 T2 还想更进一步

那就只剩视频了。路径是：拿这 11 张当角色参考，AI 生成 **10 秒绿幕视频**，再抠像转 webm（VP9 + alpha）。

关键参数（大肥鱼就是这么做的）：
- 背景纯 `#00FF00`
- **头顶占画面 20% 高度、脚底占 85%** —— 位置固定，不许动
- 首尾帧必须是同一个标准正面站姿（才能无缝循环）

这样每个动作就是一段视频，能做到吃饺子、放烟花、跳宅舞。

但这条路要装 ffmpeg + Python + numpy + scipy，还要生成十几段视频并逐段调参，工作量是静态图的十倍。**建议 T1/T2 跑通、桌宠真的在桌面上活着了，再考虑。**
